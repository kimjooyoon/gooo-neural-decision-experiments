# Gooo 관측 루프: 예시 하나를 더 얻어 몸체를 완성하기

2026-10-03, darwin/arm64, Go 1.27.1. 컴파일러
[`2f02d244`](https://github.com/kimjooyoon/meta-ontology-go/commit/2f02d2441b8f0bc5ce3a7920918158985b9d31c1),
SDK v0.2.16-experimental, 동결된 자체 모델을 사용했습니다.
[통합 PR 1160](https://github.com/kimjooyoon/meta-ontology-go/pull/1160)의 병합·배포 상태는 해당 PR에서 확인할 수 있습니다.
이 기록은 위 커밋으로 실제 실행한 관측입니다.

## 무엇을 물었나

세 단계의 뺄셈에서 각 피연산자 순서를 선택하면 여덟 몸체가 나옵니다.
처음 주어진 예시 `10 → -3`에는 두 몸체가 맞습니다. 그중 하나는 다른 입력에서
원하는 동작과 달라집니다. 컴파일러가 입력 `0`을 고르고, 같은 Gooo 파일에 선언된
`Expected` 함수에서 `0 → 7`을 얻으면 후보가 둘에서 하나로 줄어듭니다.

부품의 한 면만 보고는 두 개가 같아 보일 때, 차이가 드러나는 면을 한 번 더
확인하는 과정과 비슷합니다. 기준 함수는 이미 주어진 명세이며, 새로운 기대값은
그 함수의 실행에서 얻었습니다.

## 관측 결과

한 과제의 한국어·영어 지시를 각각 두 번 실행했습니다. 각 행은 네 번의 코드 생성과
생성마다 여섯 개의 실행 기대값을 포함합니다. 매번 생성 직후 Go를 빌드하고 두 번
실행했습니다. 표의 분모 24는 반복 실행을 두 배로 세지 않습니다.

| 모델 | 추가 관측 | 실행 기대값 충족 | 실제 모델 판단 | 탐색 후보 수 |
| --- | --- | ---: | ---: | ---: |
| 해제 | 없음 | 4/24 | 0 | 4 |
| 해제 | 구분할 입력만 추천 | 4/24 | 0 | 4 |
| 해제 | 기준 함수 결과 반영 | 24/24 | 0 | 32 |
| 자체 소형 모델 | 없음 | 14/24 | 4 | 4 |
| 자체 소형 모델 | 구분할 입력만 추천 | 14/24 | 4 | 4 |
| 자체 소형 모델 | 기준 함수 결과 반영 | 24/24 | 16 | 18 |

총 **24회 생성, 24회 모델 판단, 48회 컴파일된 프로그램 실행**을 수행했습니다.
추가 관측을 사용한 8회는 48/48 기대값을 맞췄습니다. 대조군을 포함한 전체는
84/144이며, 원래 예시 하나에 대한 충족률은 모든 조건에서 100%였습니다.
이 차이가 희소한 예시의 한계를 보여 줍니다.

영어 지시에서 모델은 처음부터 올바른 경로를 골랐습니다. 한국어 지시에서는
관측을 추가한 뒤 일곱 번 판단하고 여덟 후보를 검사해 완성했습니다. 추가 학습은
0회이며 모델 가중치도 그대로입니다. 이 수치는 한 과제의 표현별 관측이고, 새로운
과제 전체에 대한 정확도를 뜻하지 않습니다. 원래 예시나 추가 관측에 사용된 입력은
실행 단계에서도 선택용 입력으로 집계했습니다.
24개 실행 영수증의 `permission_boundary`는 미관측 상태로 남습니다. 기능 충족률과
실행 권한의 관측은 각각의 항목에서 읽습니다.

## 시간과 자원

아래는 각 조건 네 프로세스의 중앙값입니다. 순서는 두 번째 반복에서 뒤집었으며,
기존 Go 빌드 캐시를 사용했습니다. 수집 중 다른 로컬 소스 빌드는 실행하지 않았습니다.

| 모델 | 추가 관측 | 전체 코드 생성 ms | 프로세스 CPU, 1코어 기준 | 최대 RSS MiB |
| --- | --- | ---: | ---: | ---: |
| 해제 | 없음 | 8.27 | 88.49% | 16.71 |
| 해제 | 입력 추천 | 8.06 | 88.99% | 17.13 |
| 해제 | 기준 함수 | 8.78 | 89.45% | 17.70 |
| 자체 모델 | 없음 | 8.58 | 87.31% | 17.56 |
| 자체 모델 | 입력 추천 | 8.83 | 88.04% | 17.80 |
| 자체 모델 | 기준 함수 | 9.94 | 92.37% | 19.08 |

기준 함수 관측 단계만의 중앙값은 모델 해제 0.524 ms, 연결 0.465 ms였습니다.
프로세스 CPU는 `(user+system)/wall`이며, 컴퓨터 전체의 사용률 증가는 측정하지
않았습니다. 네 표본의 짧은 관측이므로 작은 시간 차이에는 실행 순서와 스케줄링의
영향이 있습니다. 현재 구현은 관측에서 계산한 후보를 탐색에서 다시 계산합니다.
완성된 몸체를 얻는 데는 도움이 됐고, 그 비용이 추가됐습니다.

## 다음에 줄일 일

1. 관측으로 후보가 하나가 됐을 때, 이미 검증한 계산을 재사용하는 경로를 측정합니다.
   현재 한국어 모델 조건의 추가 판단도 이 경로에서 줄일 여지가 있습니다.
2. 여러 후보가 남으면 모델과 실패 문맥이 다음 조립을 안내하도록 유지합니다.
3. 기준 함수가 없는 경우에는 권할 입력과 미해결 상태를 남깁니다. 기대값을 얻지
   못한 입력 추천만으로는 이번 과제의 기능 충족률이 늘지 않았습니다.

모델 크기보다 명세·관측·조립의 연결을 먼저 다듬는 작은 언어 기능입니다.
[연구 배경](../../docs/agile-language-research-20261003.ko.md)에서 채택한 정보 가치와
결정 일관성의 질문을, 학습 없이 유한한 후보 집합에 적용했습니다.

## 재현과 증거

수집기 소스는 연구 저장소 `25fddbb`의
[`cmd/path-observation-observe`](../../cmd/path-observation-observe)입니다.
명시한 커밋의 깨끗한 컴파일러를 빌드하고, 연구 저장소 루트에서 실행합니다.
출력 디렉터리는 새 경로여야 합니다.

```sh
go run ./cmd/path-observation-observe \
  --compiler /explicit/path/to/gooo \
  --compiler-sha 2f02d2441b8f0bc5ce3a7920918158985b9d31c1 \
  --go-bin /explicit/path/to/go1.27.1 \
  --out publication/path-observation-loop-replay
```

모델은 `publication/full-input-separate-arithmetic-20261003/models/compact/bag-original/fp32`를
사용합니다. `manifest.json`에 컴파일러 바이너리와 모델 파일 해시를 남겼습니다.
원본 `*-generation.json`, `*-runtime.json`, 자원 관측 `processes.json`을 보존했습니다.
코드 생성은 저장소 파일을 수정하지 않으며, 런타임 영수증에는 원본 부모 기록이 들어 있습니다.

별도 Go 독자는 모델·컴파일러·생성 프로그램을 실행하지 않고 여덟 후보의 산술,
관측 후 후보 수, 추가 예시, 실제 모델 호출 수, 원본/생성 해시, 실행 결과와 선택용 입력
중복을 다시 검사합니다. 일반 문자열과 디코딩한 부모 기록에서 비공개 경로·토큰 패턴도
확인했습니다. 결과는 `independent-reading.json`이며 다음 명령으로 다시 읽을 수 있습니다.

```sh
go run ./cmd/path-observation-read --dir publication/path-observation-loop-20261003
```

기능 관련 패키지의 일반 검사·경쟁 상태 검사, 포맷·정적 분석·billing 예제 검사는
통과했습니다. 전체 로컬 검사에서는 기존 Darwin 이름공간/심볼릭 링크 관련 네 실패와
source-splitter의 임시 경로 관련 두 실패가 남았습니다. 후자는 실제 경로인
`TMPDIR=/private/tmp`에서 같은 검사 두 개가 통과했습니다. 원래 실패 기록은 보존했고,
컴파일러 CI 결과는 위 PR의 정확한 소스 커밋에 연결됩니다.
