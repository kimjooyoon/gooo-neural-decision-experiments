# 기록 값을 전달하는 Gooo 본문

2026-10-04, 컴파일러 후보 `fa3c8927`에서 관측했습니다.
[구현 PR1223](https://github.com/kimjooyoon/meta-ontology-go/pull/1223)과
[원본 기록·재현 방법](README.md)을 함께 공개합니다.

`Candidate`에 제목과 상태를 담고, 다음 활동이 그 상태를 읽어 `Review`에
요약과 사유를 담을 수 있습니다. 작은 서류를 책상 사이에 전달하는 그림과
비슷합니다. 연결마다 실제로 전달한 값, 필드의 이름과 정체성을 남겨 어디서
결과가 달라졌는지 따라갈 수 있습니다. 현재 필드는 필수 문자열 한 값이며,
활동 입력은 정수·문자열·참거짓·기록을 섞어 최대 16개까지 사용할 수 있습니다.

이번 실험에서 자체 소형 모델은 `Score`의 정수 연산 배치를 선택했습니다.
첫 후보는 0/6, 다음 후보는 6/6을 충족했습니다. 기록을 구성하고 읽는 본문은
Gooo 선언에서 생성했습니다. 모델을 끄고도 같은 소스와 Go 코드를 얻었습니다.
기존 가중치를 사용하며 이번에 새 모델을 학습하지 않았습니다.

한 그래프를 12회 반복한 관측에서 출력 기대값 432/432, 입력 슬롯 648개,
연결 전달값 432개, 필드 관측 1,152개를 확인했습니다. 추가로 두 프로세스를
함께 실행해 72/72, 저장된 구성을 새로운 8개 사례에서 실행해 96/96을
충족했습니다. 한 필드의 기대값만 바꾸면 35/36, 즉 97.22%가 일치합니다.
이 비율은 작성한 유한 기대값의 충족 범위를 말하며, 실제 `state`가 어디서
달라졌는지 기록으로 보여줍니다.

모델 추론 중앙값은 26.9μs입니다. 그래프 생성은 모델 12.80ms, 결정론
11.77ms였고, 빌드·실행까지 포함한 명령은 각각 약 344ms와 335ms였습니다.
최대 관측 메모리는 약 83MiB입니다. 프로세스와 자식 빌드의 비용이 포함돼
있습니다. 후보 확인은 8개에서 2개로 줄었지만, 생성 전체의 속도 이득은
관측하지 못했습니다. 저장 결과의 재실행은 모델 호출이 0회입니다.

다음에는 기록 필드의 선택지를 `assembling`에 직접 선언하고, CLI가 필드별
기대값과 빠진 부분을 보여주며, 이미 컴파일한 그래프를 재사용하는 방향이
유용합니다. #874의 등록형 도메인 실행 경로는 계속 별도로 남아 있습니다.
