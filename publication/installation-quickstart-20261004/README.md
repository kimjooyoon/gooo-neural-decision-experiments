# Start with the intended Go executable and retain source identity

2026-10-04. The research quickstart previously installed a fixed compiler commit
with `go install ...@revision`, then ran `gooo body-path-run` using its default
`go` lookup. Trying those instructions exposed two separate installation details.

The module install succeeds with Go1.27.1 and SDK v0.2.21. Its module version
contains the compiler's short revision, but its observed Go build information
has no `vcs.revision` or `vcs.modified`. Gooo retains that limitation explicitly:
construction and runtime receipts say `UNBOUND_LOCAL_SOURCE`; timing's source
fields say `unobserved`.

The subsequent default-tool request resolves Go1.26.5 already on PATH. Gooo
generates the body and records an actual model prediction on each request, then
stops at the Go1.27.1 runtime requirement. Both original failures and the generated
programs are retained. Their sixteen declared expectations are unobserved.

Passing the actual Go1.27.1 executable with `--go-bin` completes the same requests.
A separate clean, shallow Git checkout of main
`4f6c7566dd4390b04a48589c82eb2d9eea3a6589`, built with that executable, also
completes them and retains the full source revision in construction, runtime
and timing records. Its generated Go is identical to both module-install lanes.

| Existing authored-task lane | Constructions / model predictions | Native runs | Current finite expectations | Original first / reused response |
| --- | ---: | ---: | --- | --- |
| Module install, default Go1.26.5 | 2 / 2 | 0 | Unobserved: 16 declared | 76.28 / 60.93ms, execution failed |
| Module install, explicit Go1.27.1 | 2 / 2 | 4 | 16/16 | 1,052.71 / 65.54ms |
| Clean Git build, explicit Go1.27.1 | 2 / 2 | 4 | 16/16 | 979.38 / 68.50ms |

These response intervals include decoding, construction and execution, excluding
initial model setup and saving/output. The default-tool failures do no native
execution and therefore have a different work scope. No speed improvement is
inferred. This repeats one authored order task; new intent tasks, training and
weight updates are zero. The unchanged public 16 KiB order judge makes the six
recorded predictions. The older installed-main observations remain separate.

The [root quickstart](../../README.md#try-a-local-construction) now selects the
actual tool with `GOTOOLCHAIN=go1.27.1 go env GOROOT`, builds outside a clean,
shallow checkout and passes that executable to native execution. The
[Wiki](https://github.com/kimjooyoon/meta-ontology-go/wiki/File-Based-Body-Run)
uses the explicit tool selection too. The actual CLI and worker installation
remains main `4f6c7566` / SDK v0.2.21; these separate probes do not overwrite it.

## Read the retained results

The first publication source `1bbbc6d4` failed the `runtime-and-artifacts` vet
job in [CI37170200886](https://github.com/kimjooyoon/gooo-neural-decision-experiments/actions/runs/37170200886).
Two retained `Compose` Go files in each `results` directory were discovered as
one package. The original [three errors](original-ci-failure.jsonl) remain.
The data directories are now `_results`, which Go package discovery skips.
Every retained program and observation keeps its original bytes; timing still
binds the original relative filenames. The reader explicitly consumes the data.

All three lanes retain their full source, recipe, expectations, generated Go,
response, construction, runtime, timing and original stdout/stderr. The two
build-information JSON files record observed binary hashes, Go/module/SDK versions
and original VCS settings without local filesystem paths. The read-only Go reader
checks these pins, eight int64 inputs per request, exact generated bytes, native
process outcomes, the original tool failure and every timing-sidecar file hash.
