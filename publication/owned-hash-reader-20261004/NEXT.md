# 다음 작은 실험의 범위

2026-10-04. 아래 두 가지는 다음 후보의 계획입니다. 현재 설치·비교 결과는 이
폴더의 README와 원본 기록에서 읽습니다.

## 1. 반복 실행의 시작 비용 줄이기

재사용 요청에서도 두 실제 프로세스 시작·대기가 큰 구간입니다. 순수
Integer→Integer 바디 한 개를 다루는 Go 실행기를 보관해, 고정 길이 배열의 요청을
차례로 받는 작은 실험을 우선 검토합니다. 요청당 두 함수 평가와 새로 시작한
프로세스 수를 각각 기록하고, 지금의 두 새 프로세스 실행과 비교합니다.

이 경로에는 자체 기록 형식을 둡니다. 과거 시작·CPU를 현재 작업으로 집계하지
않도록 각 요청의 순번, 바디 지문, 입력·출력 수, 현재 CPU 구간을 연결합니다.
시간 초과, 취소, EOF, 잘못된 순번, 바디 변경, 자식 종료를 먼저 실패시키고 원본을
보존합니다. 원래 Go와 유한 기대값을 고정해 결과·첫 요청·재사용 요청·메모리를
함께 읽습니다. 현재 파일 확인을 유지하는 비용도 따로 기록합니다.

## 2. 자체 작은 행렬의 세 값 저장 실험

[BitNet b1.58의 연구](https://arxiv.org/abs/2402.17764)는 가중치를 -1/0/1 세 값으로
표현하는 방향을 소개했습니다. Microsoft와 연구자들의 이 아이디어를 참고해
우리의 4,096개 선택 가중치에서도 세 값 표현을 작게 실험할 계획입니다.

저장 계산의 한 후보는 다섯 세 값 숫자를 한 바이트에 넣는 방식입니다.
3^5=243이므로 가중치 본체는 ceil(4096/5)=820바이트, 행별 FP32 스케일 128개는
512바이트로 합계 1,332바이트가 됩니다. 이는 제안한 본체 배치의 계산이며 실제
모델 파일·메타데이터·실행 RAM의 측정 결과는 이후에 기록합니다.

기존 FP32 선택, 단순 세 값 변환, 작은 후속 조정 순으로 확인합니다. 같은 공개
한영 원본에서 첫 충족 후보의 비율, 필요한 후보 평가 수, 최종 유한 기대값,
선택이 바뀐 원본, 호출 시간과 실제 배열 크기를 함께 남깁니다. 표현을 줄여 생기는
오류도 다음 조립의 사실로 사용합니다. 결과가 아직 확인되지 않은 경우에는
모델 후보를 별도로 보관해 현재 공개 가중치와 비교할 수 있게 합니다.
