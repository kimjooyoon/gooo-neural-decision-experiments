## 현재 후보: 모델 파일까지 같은 읽기 경계 적용

추가 조사에서 모델 정보 JSON과 자체 order-judge의 `weights.bin`도 쓰기 상대 없는
FIFO일 때 파일 열기에서 기다리는 것을 실제 CLI로 재현했습니다. 원래 설치본의
두 요청은 500ms 뒤 컨트롤러가 쓰기 쪽을 열자 파일 종류 오류와 종료 1을 반환했습니다.
현재 후보는 소스 입력·모델 정보·order-judge 가중치에 같은 Unix 비차단 열기를 사용합니다.
열린 파일의 종류와 기존 크기·형식·가중치 검증을 계속 적용합니다.

| 현재 후보의 별도 관측 | 결과 |
| --- | --- |
| 소스 경로 교체 64회 | 일반 파일 완료 25회, 생성 전 파일 오류 39회 |
| 외부 FIFO 해제·시간 초과 | 각각 0회; 모든 프로세스 종료 확인 |
| 위 25회 실제 바디 실행 | 50회, 3,200/3,200 기대값, 고정 Go 25개 일치 |
| 모델 정보·가중치 FIFO | 모두 해제 없이 파일 오류, 결과 폴더 생성 전 종료 |
| 별도 한영 모델·결정론 실행 | 생성 8회, 자체 판단 4회, 바디 실행 16회, 1,024/1,024 |

모델 정보 FIFO 첫 요청은 총 528.789584ms, 가중치 FIFO는 7.274167ms였습니다.
첫 요청의 시간을 생략하지 않으며 일반 처리 속도 개선율로 환산하지 않습니다.
별도 정상 모델 요청의 첫/재사용 응답은 한국어 298.670458/25.321709ms,
영어 485.046083/27.571583ms였습니다. 결정론 첫/재사용은
307.617500/26.578709ms와 305.768084/26.236875ms입니다.
정상 요청의 응답 시간은 바디 생성과 실제 실행을 포함합니다.
모델 판단만의 시간은 별도로 측정하지 않았습니다.
새 의도·학습·가중치 갱신은 0개이며 CPU 사용률과 모델 단독 RAM은 미관측입니다.

모델 정보는 64KiB 이내이고 order-judge 가중치는 정확히 16,384바이트입니다.
다른 모델 프로필의 후속 아티팩트 읽기는 각 기존 로더가 담당합니다.
Unix 실행 증거와 Windows arm64 교차 컴파일 증거를 구분합니다.

현재 후보 원본은 `revision2-native-observations.zip`에 별도로 보관했습니다.
622개 파일·8,879,667 regular bytes, SHA256
`0dd3d0e451099532cb3c211088060227aefb29042be68c2abbb1b933c053ebcb`입니다.
`revision2-swap-readback.json`과 `model-io-readback.json`은 원본 결과의 읽기 전용 확인입니다.

## 별도 실행기로 병렬 요청하기

배포 후보 `22c2c914`에서 바디 실행기를 따로 빌드하고 각 모드에 한영 요청을
동시에 두 개씩 보냈습니다. 모델 사용·결정론 4개 구성, 자체 판단 2회, 실제 실행
8회에서 **512/512**와 기존 생성 Go를 유지했습니다. 두 프로세스는 EOF까지
종료를 확인했고 시간 초과는 0회였습니다. 모델 모드 총 1,405.621083ms·결정론
614.624000ms는 모델 준비·동시 요청 생성/실행·프로세스 종료를 포함합니다.
처리량이나 모델 단독 성능으로 일반화하지 않습니다.

`candidate-worker-observations`와 빌드 정보·수집기를 보관합니다. 원본 수집기의
`installed` 문구가 가리키는 실제 바이너리는 이 배포 후보입니다. 후속 수집기는
설치 여부를 가정하지 않고 전달받은 깨끗한 소스로 표시합니다.

## 실제로 발견한 대기

`body-path-run`은 원래 경로의 종류를 확인한 다음 파일을 열었습니다. 그 사이에
경로가 쓰기 상대 없는 FIFO를 가리키면 파일을 여는 호출에서 기다렸습니다.
소스 읽기가 끝나지 않아 모델 준비·결과 폴더 생성에도 도달하지 못했습니다.

깨끗한 설치본에서 소스 경로를 일반 파일/FIFO의 심볼릭 링크로 원자적으로
교체했습니다. 14번째 실제 CLI 요청에서 컨트롤러가 500ms 뒤 유일한 FIFO
쓰기 쪽을 열자 프로세스가 원래 파일 종류 오류를 반환하고 종료했습니다.
이 500ms는 컨트롤러의 해제 시점입니다. 원래의 자연 종료 시간으로 해석하지 않습니다.
모든 원본 stdout/stderr·프로세스 결과를 남겼고 시간 초과만으로 문제를 판정하지 않았습니다.

## 초기 후보 `1a47cb16`의 변경과 원본 관측

Unix는 파일을 비차단으로 연 뒤 열린 파일 자체의 종류·크기를 검사합니다.
소스·레시피·기대값·옵션에 같은 읽기 함수가 적용됩니다. 일반 파일의 심볼릭
링크는 원래 bytes를 유지합니다. UTF-8·빈 파일·크기 상한 검사도 유지합니다.
파일 없음·권한 오류는 원래 파일시스템 원인을 전달합니다. 다른 플랫폼은 열기
전 종류 확인과 연 뒤 검사를 유지합니다. Windows arm64는 교차 컴파일만 확인했습니다.

후보의 실제 경로 교체 64회는 쓰기 쪽 해제·시간 초과 0회로 모두 종료했습니다.
그중 일반 파일을 읽은 32회는 기존 생성 Go와 실제 출력을 유지했고, FIFO를 읽으려던
32회는 결과 폴더를 만들기 전에 파일 오류로 종료했습니다.

| 파일 상태 교체 실험 | 요청 | 일반 파일 완료 | 생성 전 파일 오류 | 쓰기 쪽 해제 | 실제 바디 실행 | 관측 기대값 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 원래 설치본 | 14 | 6 | 8 | 1 | 12 | 768/768 |
| 수정 후보 | 64 | 32 | 32 | 0 | 64 | 4,096/4,096 |

이 표는 불안정하게 교체하는 파일의 상태별 경로 관측입니다. 두 쪽 모두 같은
기존 한국어 원본·128개 입력을 반복하며 모델 판단 0회입니다. 생성 전 파일 오류에는
runtime 관측의 기대값 분모를 붙이지 않습니다. 새 의도·학습 갱신은 0개입니다.

## 초기 후보의 자체 모델 실행

별도 한영 모델·결정론 네 조건을 각각 두 번 사용했습니다. 생성 8회·실제 자체
모델 판단 4회·바디 실행 16회에서 **1,024/1,024**와 고정 생성 Go 8개가 같았습니다.
모델 재사용 응답은 한국어 26.759375ms·영어 26.896542ms였고, 최초
297.391833·494.675875ms도 보존합니다. 결정론 재사용은 31.710292·26.496209ms입니다.
별도 공구 조회 실패는 종료 1·판단/실행 0회·기대값 128개 미관측으로 남겼습니다.
이번 자료의 처리 속도 비교·호스트 CPU 사용률·모델 단독 RAM은 미관측입니다.

자체 모델은 기존 4,096 FP32 매개변수·16,384바이트 가중치를 사용했습니다.
가중치 SHA256은 `cf00ccc83d17d28ed73fcb869366151a48ffccd3aa8ca8e635aabf19810b9e78`로 같습니다.
기존 두 의도의 반복이며 경로 교체 실험과 따로 집계합니다.

## 증거와 다시 읽기

`native-observations.zip`은 807개 파일·12,296,808 regular bytes입니다.
ZIP SHA256은 `23bb0c253a9c136074e2dfa6df36d40e26610f4755ba9e5eb1867e0d9c2e0f2e`입니다.
모든 파일과 닫힌 목록을 대조했습니다. `swap-readback.json`은 실제 38개 일반
파일 완료의 입력·출력·재실행·고정 Go·깨끗한 생산 소스와 실제 판단 0회를 확인합니다.
읽기 전용 확인 자체의 생성·모델 판단·바디 실행은 0회입니다.

```sh
unzip native-observations.zip -d saved
go run ./archive-readback native-observations.zip saved
go run ./swap-readback saved saved/inputs saved/expected
unzip -o revision2-native-observations.zip -d saved
go run ./archive-readback revision2-native-observations.zip saved
go run ./swap-readback saved saved/inputs saved/expected revision2
go run ./model-io-readback saved
GOOO_LOCAL_GO=/path/to/go1.27.1/bin/go go run ./race-probe \
  /path/to/clean-gooo saved/inputs fresh-swap-output 64
```

위 두 ZIP을 새 폴더에서 풀고 보관된 결과를 확인하는 순서도 직접 실행했습니다.
`public-cli-*.json`에 각 읽기 전용 확인을 남겼습니다.

새 경로 교체 실행은 스케줄링에 따라 다른 완료/오류 목록을 만듭니다.
`swap-readback`은 보관한 원래 14/64회 자료와 선택한 현재 후보 64회 자료를 확인합니다. `race-probe`는 Unix에서
자신이 만든 FIFO만 해제하고 모든 실제 프로세스·교체 루프를 종료한 뒤 제거합니다.

원래 `os.Open`을 그대로 추출한 경계의 단위 테스트도 1초 대기를 재현하고
쓰기 쪽 해제·종료 확인 뒤 실패를 기록했습니다. `pre-fix-open-boundary.go.txt`와
`first-open-tests.raw`에 이 범위를 보존합니다. 수정 뒤 네 입력의 FIFO 거부·일반
심볼릭 링크·잘못된 크기/UTF-8·파일시스템 원인 확인, 전체 바디 구간 race·CLI·
전체 vet·Go1.27.1 modernizer 고정점은 통과했습니다. source IR·원본 선언·보호된
검증 의미·CI 정책과 생성/runtime JSON·상태·종료 계약은 유지합니다.
