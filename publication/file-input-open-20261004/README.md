## 실제로 발견한 대기

`body-path-run`은 원래 경로의 종류를 확인한 다음 파일을 열었습니다. 그 사이에
경로가 쓰기 상대 없는 FIFO를 가리키면 파일을 여는 호출에서 기다렸습니다.
소스 읽기가 끝나지 않아 모델 준비·결과 폴더 생성에도 도달하지 못했습니다.

깨끗한 설치본에서 소스 경로를 일반 파일/FIFO의 심볼릭 링크로 원자적으로
교체했습니다. 14번째 실제 CLI 요청에서 컨트롤러가 500ms 뒤 유일한 FIFO
쓰기 쪽을 열자 프로세스가 원래 파일 종류 오류를 반환하고 종료했습니다.
이 500ms는 컨트롤러의 해제 시점입니다. 원래의 자연 종료 시간으로 해석하지 않습니다.
모든 원본 stdout/stderr·프로세스 결과를 남겼고 시간 초과만으로 문제를 판정하지 않았습니다.

## 후보의 변경

Unix는 파일을 비차단으로 연 뒤 열린 파일 자체의 종류·크기를 검사합니다.
소스·레시피·기대값·옵션에 같은 읽기 함수가 적용됩니다. 일반 파일의 심볼릭
링크는 원래 bytes를 유지합니다. UTF-8·빈 파일·크기 상한 검사도 유지합니다.
파일 없음·권한 오류는 원래 파일시스템 원인을 전달합니다. 다른 플랫폼은 열기
전 종류 확인과 연 뒤 검사를 유지합니다. Windows arm64는 교차 컴파일만 확인했습니다.

후보의 실제 경로 교체 64회는 쓰기 쪽 해제·시간 초과 0회로 모두 종료했습니다.
그중 일반 파일을 읽은 32회는 기존 생성 Go와 실제 출력을 유지했고, FIFO를 읽으려던
32회는 결과 폴더를 만들기 전에 파일 오류로 종료했습니다.

| 파일 상태 교체 실험 | 요청 | 일반 파일 완료 | 생성 전 파일 오류 | 쓰기 쪽 해제 | 실제 바디 실행 | 관측 기대값 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 원래 설치본 | 14 | 6 | 8 | 1 | 12 | 768/768 |
| 수정 후보 | 64 | 32 | 32 | 0 | 64 | 4,096/4,096 |

이 표는 불안정하게 교체하는 파일의 상태별 경로 관측입니다. 두 쪽 모두 같은
기존 한국어 원본·128개 입력을 반복하며 모델 판단 0회입니다. 생성 전 파일 오류에는
runtime 관측의 기대값 분모를 붙이지 않습니다. 새 의도·학습 갱신은 0개입니다.

## 자체 모델로 계속 개발하기

별도 한영 모델·결정론 네 조건을 각각 두 번 사용했습니다. 생성 8회·실제 자체
모델 판단 4회·바디 실행 16회에서 **1,024/1,024**와 고정 생성 Go 8개가 같았습니다.

297.391833·494.675875ms도 보존합니다. 결정론 재사용은 31.710292·26.496209ms입니다.
별도 공구 조회 실패는 종료 1·판단/실행 0회·기대값 128개 미관측으로 남겼습니다.

기존 두 의도의 반복이며 경로 교체 실험과 따로 집계합니다.
