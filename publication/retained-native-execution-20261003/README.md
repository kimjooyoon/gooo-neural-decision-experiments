# 같은 실행파일을 보관하고 현재 입력을 새로 실행하기

2026-10-03 macOS arm64, Go 1.27.1, SDK v0.2.20. 컴파일러 후보
[`bb682032`](https://github.com/kimjooyoon/meta-ontology-go/tree/bb6820327317584d6c8a10dda1dd79f771abcb23)의
[고정 프로토콜과 Go 수집기](https://github.com/kimjooyoon/meta-ontology-go/tree/bb6820327317584d6c8a10dda1dd79f771abcb23/examples/retained-native-runtime)를
사용했습니다. [#1184](https://github.com/kimjooyoon/meta-ontology-go/pull/1184)의 병합·배포 상태는 GitHub에서 확인할 수 있습니다.

Gooo 원본과 조립 계획을 매번 다시 검증하고, 같은 조립물의 실행파일 한 개를
검사대 위에 보관했습니다. 현재 입력 배열을 보내 두 번 실행하고 새 기대값과
비교합니다. 이전 합격 판정과 이전 빌드 비용은 현재 관측에 포함하지 않습니다.

## 완료한 관측

기존 네 계산 계열의 한영 개발 소스 64개, 시도 예산 1·8, 원본 실행기·보관 실행기,
각 두 번 호출입니다. 소스/예산 쌍마다 두 실행기의 순서를 번갈아 배치했습니다.
양쪽 모두 두 호출 동안 모델 생성기와 후보 준비를 보관하므로 실행파일 소유권을
비교합니다. 추가 학습은 0회, 가중치는 공개된 최초 16 KiB 모델과 같습니다.

| 실제 관측 | 수 |
| --- | ---: |
| 소스 | 64 |
| 생성과 실제 모델 판단 | 각각 512 |
| 컴파일된 프로그램 실행 | 1,024 |
| 새 빌드 / 실행파일 재사용 | 384 / 128 |
| 유한 기대값 충족 / 전체 | 3,720 / 4,096 |
| 두 번째 호출 비교에서 보관 실행기가 빠른 쌍 | 128 / 128 |

전체 선택 탐색, 순위(예측 시간 제외), 생성된 Go와 여덟 입력의 실제 결과가
고정한 최초 관측과 일치했습니다. 첫 시도에서 남아 있던 미충족 결과도 보존했습니다.
성공 사례를 골라서 시간과 정답률의 분모를 줄이지 않았습니다.

## 같은 조립물의 두 번째 호출 비용

다음은 각 128회 관측의 중앙값입니다. 전체 생성 시간이나 최초 실행 비용과 구분합니다.

| 구간·관측 | 매번 빌드 | 실행파일 보관 |
| --- | ---: | ---: |
| 실행 관측 전체 | 293.60ms | 28.89ms |
| 현재 호출의 빌드 | 105.74ms | 새 빌드 0회 |
| 첫 프로그램 실행 | 163.58ms | 2.88ms |
| 두 번째 프로그램 실행 | 3.43ms | 2.64ms |
| 현재 자식 프로세스 CPU 합 | 214.98ms | 9.76ms |
| 현재 자식 중 최대 단일 프로세스 RSS | 86,171,648B | 14,483,456B |

쌍별 실행 관측 절약 중앙값은 264.48ms, 범위 238.69~633.40ms입니다.
새 파일의 첫 실행 비용도 줄었지만, OS 최초 실행 지연의 원인은 분리하지 않았습니다.
보관 실행기의 첫 호출은 중앙값 299.50ms로 여전히 빌드와 최초 실행을 수행했습니다.
호스트 캐시·스케줄링 변동과 수집 도중의 로컬 검사·예제 실행이 있습니다.
배포 환경별 효과는 후속 관측이 필요합니다.

CPU는 현재 버전 조회·실제 빌드·두 실행의 사용자+시스템 시간입니다. 보관 호출에서는
이전 빌드를 제외합니다. RSS는 현재 자식 중 최대값이며 부모·전체 호스트 메모리나
모델 자체 메모리와 다릅니다. 전체 수집 프로세스의 시간 기록도 별도로 보관했습니다.
임시 저장 공간 바이트는 이번 수집에서 계측하지 않았습니다. 구현은 인스턴스당
한 작업 폴더를 소유하고 닫을 때 제거하며, 무제한 실행파일 캐시는 없습니다.

## 실제 Go 예제

[Go 예제 소스 `0cb08ce`](https://github.com/kimjooyoon/gooo-neural-decision-experiments/tree/0cb08ce/cmd/order-example)에서
`--retain-native`를 사용했습니다. 생성되면 같은 스트림 안에서 바로 실행합니다.
모델·결정론 경로 각각 두 번, 합계 4회 생성·2회 판단·8회 실제 실행과 32/32 기대값을
확인했습니다. 모든 바디는 앞선 공개 예제와 같습니다.

| 경로 | 첫 응답 / 다음 응답 | 첫 실행 관측 / 다음 실행 관측 |
| --- | --- | --- |
| 자체 모델 | 967.38 / 24.41ms | 276.68 / 22.30ms |
| 모델 생략 | 433.50 / 24.90ms | 427.80 / 22.75ms |

응답 시간은 생성과 실행을 포함한 왕복 시간입니다. 실행 관측은 그 안의 구간이므로
둘을 더하지 않습니다. 첫 응답에는 프로세스 시작 비용이 포함됩니다. 두 번째 요청은
실행파일을 재사용하며, 모델 경로는 새 판단을 한 번 더 수행합니다.

## 실패와 검증

최초 수집은 `3e607553`에서 부모 관측 비교를 거부했습니다. 메모리 안의 타입 구조와
JSON에서 읽은 맵의 필드 순서가 달랐습니다. 두 관측을 같은 정확한 숫자 디코더로
검증한 후 비교하도록 수정했고, 부모의 실제 값이 바뀌면 계속 거부하는 회귀를
추가했습니다. [최초 관측](initial-failure.zip)과 [실패 기록](initial-failure.txt)을 남겼습니다.
별도의 취소 회귀도 짧은 시작 시간 제한 대신 실제 실행 시작을 확인한 뒤 취소하도록
수정했습니다. 해당 초기 로컬 실패는 작업 증거에 보존했습니다.

소스·계획·부모 위조, 실행파일 변조/삭제, Go 도구 바이트 변경, 새 입력/틀린 기대값,
빌드·실행 취소, 종료 뒤 호출, 반복 종료와 동시 입력 분리를 검사했습니다.
bodyexecution/bodypathstream/cmd-gooo의 로컬 race 검사와 전체 vet가 통과했습니다.
Go 예제의 분리 실행·보관 실행·미충족 결과·취소 회귀도 통과했습니다.
필수 여섯 CI와 원본 증거에 따른 배포 기록은 완료 후 별도로 추가합니다.

## 재계산과 원본

[원본 전체 ZIP](raw.zip)에는 512개의 생성·실행 기록, 각 소스·레시피·독립 기대값,
저널·완료 manifest가 있습니다. [summary.json](summary.json)은
[Go 집계기](../../cmd/retained-native-summary)로 계산했습니다.

```sh
unzip raw.zip -d /tmp/retained-native-records
go run ./cmd/retained-native-summary /tmp/retained-native-records/records.json
```

`model-example/`과 `deterministic-example/`에 두 요청의 원본 응답과 실행 기록이 있습니다.
모델은 허용된 후보의 순위를 제안하고, Gooo가 조립·재검증·유한 실행 관측을 담당합니다.
현재 범위는 지원되는 순수 Integer→Integer 바디와 이미 관측한 개발 과제입니다.
