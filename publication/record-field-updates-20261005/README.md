# Sequential field code generation

Gooo에서 필드를 하나씩 갱신하고, 그 값을 다음 필드가 사용하는 코드를 조립했습니다.
예를 들어 제목을 정하고 상태를 바꾼 다음, 바뀐 두 값으로 설명을 만듭니다.
레코드 전체를 복사해 두거나 필드 하나를 저장해 두는 경우도 실행했습니다.

```gooo
let copy = input0
copy.title = "draft"
copy.state = "wait"
copy.reason = "deferred"
return copy
```

Gooo의 `field_update` 선택이 위 세 대입식에 각각 원래 제목,`"ready"`,
`copy.title + ":" + copy.state`를 넣을 수 있게 합니다. 모델은 허용된 부품의
조립 순서를 고르고, 현재 변수 값과 실행 순서는 언어가 처리합니다.

## 관측

사전 계획한 여섯 코드 형태에 한글/영어,결정론적/QAT,시도1/2/8을 적용했습니다.
유효한 소스72개 그래프는 각각 네 입력으로 두 번 실행했습니다. 앞선 공유 필드
모델의 공개 가중치를 그대로 사용했고 추가 학습은0회입니다.

| 방식·시도 예산 | 맞은 실행 필드 | 맞은 활동 출력 | 실제 후보 평가 횟수 | 전체 명령 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 결정론적1 | 12/144 | 8/96 | 12 | 311.13ms |
| 결정론적2 | 56/144 | 8/96 | 24 | 313.29ms |
| 결정론적8 | 144/144 | 96/96 | 96 | 318.47ms |
| QAT1 | 144/144 | 96/96 | 12 | 313.29ms |
| QAT2 | 144/144 | 96/96 | 12 | 310.10ms |
| QAT8 | 144/144 | 96/96 | 12 | 313.00ms |

각 행은 여섯 형태×두 언어의12개 그래프입니다. QAT 추론 중앙값은
17.50~18.46µs였습니다. 명령 CPU시간 중앙값은246.76~252.54ms,
최대 RSS는83.86MiB였습니다. 이 RSS는 네이티브 빌드를 포함하는 명령 관측입니다.
입력 해석·타입 검사·빌드·실행도 포함한 전체 시간에서는 속도 차이를 확인하기
어렵습니다. CPU시간/벽시계시간은 한 코어 기준 평균이며 컴퓨터 전체 사용률
상승과 GPU 사용률은 측정하지 않았습니다.

**이번 목표 조합은 모두 mask7(세 대안식 선택)입니다.** 모델이 같은 선택을
반복하는 편향으로도 높은 점수가 가능합니다. 선택용 입력과 네이티브 실행 입력도
같습니다. 여기서 확인한 것은 여섯 순차 코드 형태의 실행과 재구성,그 안에서의
관측된 후보 순위입니다. 표현이 달라진 앞선 실험의 낮은 판단률과 회귀는 유지됩니다.
이 실험 하나와72개 반복 관측을 구분하며100개 독립 접근은 아직 진행 중입니다.

## 실패를 남긴 소스 준비

최초72개 예정 실행 중24개는 저장한 변수가 기본식에서 사용되지 않아 실행 전
검사에 걸렸습니다.48개 그래프만96회 네이티브 실행까지 갔습니다.
실패 소스·오류와 모든 첫 관측은`native-initial.zip`에 보존했습니다.
저장한 레코드는`saved.state`,문자열은`saved`를 기본식에서 읽도록 고쳤습니다.
수정 계획을 공개한 뒤 동일한72개 조합을 다시 실행했고`native-valid.zip`에
담았습니다. 모델·목표·입력·시도 예산을 바꾼 학습은 수행하지 않았습니다.
두 단계의 원본 합계7,590,125 B는 등록한16MiB 한도 안에 있습니다.
압축 파일은 원본 모든 파일과 바이트가 같은지 확인했습니다.

## 재현과 다음 작업

컴파일러 후보`f070e7743688815db7684134a42d01256ea3f9a0`는 깨끗한 Go1.27.1
빌드이며 SDKv0.2.23을 사용합니다. [언어 PR1233](https://github.com/kimjooyoon/meta-ontology-go/pull/1233)이
병합 검사를 진행 중입니다. 모델은
[공개 QAT](https://huggingface.co/asketeddy/gooo-record-shared-field-tiny-v1/tree/cd994c1b1e952924c6ce7e821fc3db25bcc81c25/models/qat_ternary)를
사용했습니다. 모델 입력에는 허용된 식·필드·의도가 들어가고 테스트 결과는 제외됩니다.

```sh
go run ./cmd/record-update-study --gooo /path/to/gooo --go-bin /path/to/go1.27.1 \
  --model /path/to/models/qat_ternary/model.json --out /tmp/field-update-observation
go run ./cmd/record-update-study --audit /tmp/field-update-observation
```

Go 감사기는 원본 파일 해시,수동 정의한 형태별 기대값,선택 필드와 실제 실행
필드,현재 입력 전달,후속 Label 값,빌드·두 실행의 완료,호출 수를 다시 확인합니다.
실행과 저장된 조립의 재구성은 새 모델 호출0회입니다.

모델의 현재 특징은 식의 모양만 읽고,지역 변수의 현재 정의와 이전 갱신을
해결하지 않습니다. 다음에는 서로 다른 목표 조합과 부정·혼합 요구를 넣고,
현재 값이 어디서 왔는지를 작은 입력 배열에 표현하겠습니다. 언어에서 그
의존 관계를 실행할 수 있게 된 것이 이번 변화입니다.
