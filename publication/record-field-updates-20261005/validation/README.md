# 순차 필드 조립: Linux·설치본 확인

원래 실험의 후보 소스는 `f070e774`, 배포한 main은 `a5f6e8c6`입니다.
두 소스의 트리는 같으며 설치본은 Go1.27.1·SDKv0.2.23 빌드입니다.
개발·main은 각12개 검사와 독립 증거 확인 후 병합했습니다.
검사 번호·원본 ZIP 지문은 두 `*-proof-verification.json`에 있습니다.

## 다른 환경과 새 설치본

- `linux-ci.zip`: 연구 CI37232824834의 원래 아티팩트입니다.
- `linux-verification.json`: 아티팩트 해시와72개 관측의 후보·응답·값 비교입니다.
- `linux-audit.json`: 모든 실행 필드와 형태별 기대값을 원본에서 다시 계산했습니다.
- `research-ci.json`: 해당 소스의 전체27개 작업이 완료·성공한 공개 상태입니다.
- `installed-native.zip`: 새 설치본으로 추가 실행한72개 그래프·144회 실행의 원본입니다.
- `installed-audit.json`: 추가 원본의 독립 필드·후속 입력·출력 재계산입니다.
- `installed-validation.json`: 원래 Mac과 설치본의72개 소스·문맥·응답·후보·
  실행 값이 같음을 확인하고 두 작업자의 별도 관측을 함께 담았습니다.
- `installed-quickstart-summary.txt`: 설치 준비 단계의 선택 필드15/15개,
  새 실행 출력14/14개·레코드 필드21/21개를 짧게 읽은 결과입니다.

설치 후 전체 명령 중앙값은320.34~503.66ms였습니다. QAT 추론은17.96~18.63µs입니다.
원래 Mac의310.10~318.47ms와 따로 기록합니다. 첫 결정론 묶음의 느린 관측도
유지했습니다. 비용 차이의 원인을 이 자료만으로 특정하지 않습니다.
추가 측정에서도 모든 목표는mask7입니다. 한영 의도 일반화 지표와 구분합니다.

감사기는 연구 루트의 `cmd/record-update-study --audit <압축 해제 폴더>`로 실행합니다.
압축 해제에는 새 폴더를 사용합니다. 저장 원본은 바이트를 바꾸지 않았습니다.

## 두 작업자로 바로 응답하기

`worker-raw.zip`은 첫 관측과 반복3회의 응답·준비·요약12개 파일입니다.
압축하기 전 모든 원본과 다시 비교했습니다. 관측마다32개 요청을 완료하고
선택 필드384/384개를 충족했습니다. 여섯 본문 형태×두 언어를 반복했으며
목표 조합은 동일합니다. 새 모델 호출은 요청마다1회였습니다.

첫 요청의 응답을 받은 뒤에만 나머지 요청을 보내고 입력을 닫았습니다.
4회 모두 입력 종료 전에 첫 응답이 도착했습니다. 첫 응답은525.86ms,
반복3회는10.37·6.71·6.72ms입니다. 작업자 최대 RSS는22.88~23.41MiB였습니다.
32개 전체 처리의 벽시간과 CPU시간은 각 원본에 있습니다. CPU시간/벽시간은
코어 기준 평균이며 호스트 CPU 증가량은 측정하지 않았습니다.
이 관측은 작업자의 선택·코드 생성이며 그래프의 실제 실행은 위 네이티브 자료에서 읽습니다.

표준 Go만 사용하는 재현 도구:

  /path/to/gooo-body-worker /path/to/unpacked-native-valid \
  /path/to/models/qat_ternary/model.json /tmp/new-worker-observation \

## 설치와 용량

`installation.json`은 소스·트리·두 실행 파일의 해시와 SDK를 기록합니다.
공개본의 실행 파일 경로는 이동 가능한 이름으로 바꿨습니다. 원래 설치 기록은
로컬에 보존합니다. `compiler-build.json`은 깨끗한 빌드의 출처입니다.

원래 Mac과 Linux 원본12,041,966 B는16MiB 목표 안입니다. 설치 후72개 관측과
작업자 원본을 추가한 합계는19,906,084 B(18.98MiB)로 그 목표를 넘었습니다.
추가 자료와 실패를 유지하고, 공개본은 압축으로 보관합니다. `storage.json`은
원래 범위, `installed-validation.json`은 추가 원본까지 합친 분모를 제공합니다.

`local-cleanup.json`은 새 설치본과 이전2c 롤백 쌍을 확인한 뒤 삭제한 중복
실행 파일3개의 해시·출처·크기입니다. 파일 크기 합계57,681,206 B를 지웠습니다.
모델·데이터·실험 원본과 이전2c 롤백 쌍은 보존했습니다.
