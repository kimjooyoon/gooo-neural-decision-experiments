# 파일로 Gooo 바디를 조립하고 바로 실행하기

2026-10-03. 컴파일러 [PR #1186](https://github.com/kimjooyoon/meta-ontology-go/pull/1186),
두 번째 측정 소스 [`24dc98a0`](https://github.com/kimjooyoon/meta-ontology-go/tree/24dc98a05fb4577201adf0b34a6954e00a0aeb6a).
개발 PR은 정규 CI·독립 증거 검증 뒤 `92e2c017`로 병합했습니다.
[main 승격 #1187](https://github.com/kimjooyoon/meta-ontology-go/pull/1187)도 정규 CI와
독립 증거 확인 뒤 병합했습니다. 깨끗한 main
[`fc854ef4`](https://github.com/kimjooyoon/meta-ontology-go/tree/fc854ef49be02644006c956c652e60cc8d1d06bf)를
Go 1.27.1로 빌드해 로컬에 설치하고 아래의 사용 명령을 재실행했습니다.
이전 설치본 `8c6ec01c`의
스트림 실행 경로에서, 파일을 지정하는 `body-path-run` 명령으로 진행한 사용성 실험입니다.

소스는 설계도, 레시피는 허용한 조립 순서, 기대값은 완성품을 확인하는 작은 측정표로
읽을 수 있습니다. 모델은 가능한 조립물의 순위를 정하고, Gooo가 선언한 예시와
현재 실제 실행을 확인합니다. 무엇을 충족했는지와 남은 차이는 결과 파일에 남습니다.

## 사용하기

위 main에서 빌드한 `gooo`와 Go 1.27.1을 준비하고 연구 저장소 루트에서 실행합니다.

```sh
gooo body-path-run \
  --source examples/whole-candidate-order/source.gooo --activity Compose \
  --path-plan examples/whole-candidate-order/recipe.json \
  --cases examples/whole-candidate-order/cases.json \
  --model publication/order-judge-initial-20261003/model.json \
  --repeat 2 --out file-body-results
```

모델 옵션을 생략하면 결정론적으로 진행합니다. `--activity`에는 자신의 소스 활동
이름을 지정할 수 있습니다. `--out`은 새 경로이며, 기존 폴더를 지정하면 종료합니다.
생성된 Go를 `run-N-generated.go`로 직접 읽을 수 있고, 원본·레시피·기대값,
세대별 생성·실행 기록과 `summary.json`도 함께 저장합니다. 입력 JSON 줄이나
실행을 연결하는 Go 예제 프로그램을 준비하는 단계가 줄었습니다.

`--options options.json`으로 CI 문맥, 후보 구별과 관측 설정을 전달할 수 있습니다.
CI 상태는 호출자의 문맥이며 피드백을 지원하는 로컬 모델, `step_attempts`,
`feedback_rounds`가 필요합니다. 현재 whole-candidate order 모델은 기본 유한
탐색을 사용하고 CI 피드백·배치 옵션을 거부합니다. 소스 검증과 실제 실행은
현재 요청에서 수행합니다. CI-only 옵션의 거부도 회귀 검사로 남겼습니다.
반복 횟수 1..16, 실행 입력 1..128, 지원 바디는 순수 Integer→Integer입니다.
관측이 완료되고 일부 기대값이 미충족인 경우에는 종료 코드 0과 해당 분모·분자를
남깁니다. 생성 거부·실행 오류는 원본 결과를 저장하고 종료 코드 1을 반환합니다.
사용법 오류는 2입니다. 결과 파일은 다음 요청을 시작하기 전에 저장합니다.

기대값은 Go int64 연산으로 미리 구성했고 원본 배열을 함께 보존했습니다.

## 모호한 후보를 Gooo 관측으로 구별하기

별도 레시피는 입력 10의 기대값 -3 하나를 선언합니다. `input-13`과 `7-input`이
함께 이 예시를 만족합니다. 첫 후보를 생성해 현재 입력 2, -4에서 실제 실행하면
**0/2**가 남습니다. 이 초기 결과를 보존했습니다.

같은 소스의 `Expected` 활동은 `7-input`을 선언합니다. 옵션의 관측 경로가 허용
후보 여덟 개와 탐색 입력 2, -4를 비교하고, 두 후보를 구별하는 입력 2를 선택한
뒤 그 활동에서 기대값 5를 관측합니다. 원래 선택 예시에 라벨이 추가되고 후보가
하나로 좁혀집니다. 그 후보를 직접 조립·실행한 결과는 **2/2**였습니다.
매 요청에서 이 관측을 새로 수행합니다.

원본·관측 추가·모델을 로드한 관측 추가의 세 경로를 각 두 번 실행했습니다.
**6회 생성, 12회 실제 실행**, 기대값은 원본 **0/4**, 관측 경로 각각 **4/4**입니다.
이 관측 경로의 모델 판단은 0회입니다. 모델을 로드한 경우에도 후보가 이미 하나로
정해져 순위 계산을 건너뛰었고, 그 사실을 기록했습니다. 관측은 타입 arena/Go AST
평가이며 생성한 선택 바디의 실제 두 프로세스 실행을 별도로 확인했습니다.

입력 2는 추가 선택 라벨과 겹칩니다. 이를 확인한 후 선택·탐색에 쓰지 않은 입력
3, -5의 기대값 4, 12를 별도 파일로 선언해 다시 수집했습니다. 원본 **0/4**,
관측 추가 **4/4**, 합계 **4회 생성·8회 실제 실행**을 남겼습니다. 두 입력 모두
선택 예시에 없었습니다. 이 구별은 현재 선택·탐색 범위에 관한 것이며 모델 학습의
독립 평가 집합은 이 실험에서 확인하지 않았습니다.

언어가 다음에 무엇을 측정해야 할지 정하고, 관측으로 조립 후보를 줄이는 경로를
파일 기반 명령에서도 사용할 수 있었습니다. 필요한 기대값과 순수 oracle 활동의
의미는 Gooo 소스에 선언합니다. 임의 자연어 지시에 맞는 oracle을 만드는 문제는
남아 있으며, 현재 결과를 언어 전체의 정답률로 환산하지 않습니다.

## 발견한 문제와 확인 범위

- 초기 회귀 테스트도 단일 예시의 모호함에서 0/2를 기록했습니다. 테스트에서는
  두 번째 선택 예시를 명시해 후보를 구분했고 실행 기대값은 그대로 유지했습니다.
- 직접 파일 경로에서도 스트림의 1 MiB 기록 제한을 적용했습니다. 실패 이유를
  stderr에서 읽을 수 있게 추가했습니다.
- 집중 race 검사와 전체 vet 통과. 실제 실행·재사용, 기존 출력 거부, 잘못된
  입력과 옵션, 기대값 누락, 부분 실패, 취소와 막힌 출력의 결과 보존을 확인했습니다.
- `completeness-delta`는 새 owned 실행의 runtime v2 기록을 현재 읽지 못합니다.
  실제 실패 원본을 보존했으며, v2 프로필과 분모 변경을 구분하는 소비자 수정이
  후속 작업입니다. [소비자 수정 #1188의 로컬·실제 모델 확인](../owned-runtime-comparison-20261003)을
  별도로 공개했고 정규 CI를 확인합니다. 현재 설치본의 지원으로 표시하지 않습니다.
  생성·실행 파일의 자체 분자·분모는 그대로 읽을 수 있습니다.
- 개발의 정규 CI 여섯 개와 원본 증거의 독립 검증은 통과했습니다.
  `dev-proof-verification.json`에 실행·아티팩트·해시를 기록합니다. main도 검증 뒤
  병합·설치하고 위의 현재 실행을 재확인했습니다.

### 인용 진단의 후속 수정

CodeQL은 `24dc98a0`에서 기존 lexer의 `quoteSource`에 새 경고를 기록했습니다.
이 함수는 알 수 없는 소스 문자를 진단 메시지에 넣습니다. 기존 작은따옴표 연결을
Go `strconv.Quote`로 바꿔 따옴표와 제어 문자를 명확하게 표시하도록 했습니다.
원본 바이트의 인용·복원, 한글·잘못된 UTF-8 바이트와 원래 진단 위치를 확인하는
검사, syntax/bodypathstream/cmdgooo의 race와 전체 vet가 통과했습니다.
[`c021fc4f`](https://github.com/kimjooyoon/meta-ontology-go/commit/c021fc4f4807478c34eb3eebea4f9b4670608817)의
CodeQL은 새 경고 0건으로 통과했습니다. 이 소스의 실제 파일 실행을 다시 수집해
8회 생성·실제 모델 판단 4회·16회 실행·1,024/1,024 기대값과 실행파일 재사용 4회를
확인했습니다. 모델 사용의 반복 응답은 한국어 31.360ms, 영어 31.922ms였습니다.
이 관측은 `quoted-source-summary.json`, `quoted-source-native.zip`에 별도로 남습니다.
앞선 측정의 소스와 결과는 그대로 유지합니다.

이후 [`36a22d9d`](https://github.com/kimjooyoon/meta-ontology-go/commit/36a22d9d52fc56052df4be175685727f26948a85)는
CI 피드백 옵션의 제약을 문서와 회귀 검사에 추가했습니다. 이 마지막 소스의 정규
CI와 독립 증거 검증을 통과했습니다. 그 소스의 조건 분기·지역 참조·선언 순서
예제도 2회 생성·4회 실행·6/6 기대값을 확인했고 두 번째 실행파일을 재사용했습니다.
`exact-final-compound.zip`에 원본을 남겼습니다. 마지막 소스의 CodeQL 분석은
통과했고 PR 경고 비교는 설정 누락으로 NEUTRAL입니다. 부가 GitHub AI 보안 리뷰는
월간 할당량 초과로 실행하지 못했습니다. 이 상태들을 `exact-final-security-summary.json`에
분리해서 기록했습니다. 앞선 소스의 결과를 마지막 소스의 결과로 대체하지 않습니다.

이 디렉터리의 압축본은 정상 결과와 미충족 관측을 함께 포함합니다. 새 입력 묶음과
