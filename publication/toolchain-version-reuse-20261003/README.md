2026-10-03. [컴파일러 개발 PR #1192](https://github.com/kimjooyoon/meta-ontology-go/pull/1192).
개선 소스의 실제 실행과 기록 읽기를 완료했습니다. 개발 #1192의 필수 여섯 검사와
정확한 소스의 불변 증거를 독립 확인해 병합했습니다. 개발 소스 `384df90b`와

자체 검사를 진행하고 있습니다.

## 사용자가 받는 변화

`gooo body-path-run --repeat 6`은 소스와 레시피로 바디를 조립한 뒤 바로 실행합니다.
같은 프로세스에서 반복할 때 정규 Go 실행파일의 첫 버전 확인을 보관합니다. 별도
캐시 옵션은 없습니다. 현재 Go 파일 전체의 해시·내장 버전·플랫폼·실행 환경이
일치할 때만 보관한 확인을 씁니다. 셸 래퍼는 매번 새 버전 프로세스를 실행합니다.

바디를 만들 때마다 원본·계획·선택·부모 기록을 다시 확인하고, 현재 실행파일의
내용을 확인한 뒤 현재 입력을 두 번 실행합니다. 기대값이 바뀌면 새 결과를 남깁니다.
모델을 생략하면 결정론적 조립을 사용합니다.

## 같은 조건에서 번갈아 실행한 측정

기존 clamp 조건으로 감싼 한영 순서 조립 파일 두 개와 128개 기대값을 유지했습니다.
각 언어의 모델·결정론 경로에 대해 **기존 → 개선 → 개선 → 기존** 순으로 네
프로세스를 실행했습니다. 각 프로세스는 여섯 요청을 처리했습니다. 첫 요청은 실제
버전 확인과 빌드를 수행하고, 뒤의 다섯 요청은 같은 실행파일로 현재 사례를 실행했습니다.

| 관측 | 기존 | 개선 |
| --- | ---: | ---: |
| 조립 요청 | 48 | 48 |
| 실제 모델 판단 | 24 | 24 |
| Go 버전 자식 프로세스 | 48 | 8 |
| 실제 Go 빌드 | 8 | 8 |
| 조립한 프로그램 실행 | 96 | 96 |
| 유한 기대값 | 6,144/6,144 | 6,144/6,144 |
| 최초 응답 중앙값, 각 8회 | 659.25ms | 630.17ms |
| 반복 응답 중앙값, 각 40회 | 79.91ms | 63.69ms |
| 반복 응답 범위 | 74.51–86.18ms | 57.19–72.27ms |
| 현재 자식 CPU 합 중앙값 | 31.21ms | 13.37ms |
| 현재 자식 중 최대 단일 RSS 중앙값 | 14.28MB | 4.42MB |

반복 응답 중앙값은 약 20.3% 줄었습니다. 네 조건의 중앙값도 각각 줄었습니다.
한국어 모델 80.37→63.69ms, 한국어 결정론 78.78→62.22ms,
영어 모델 82.00→64.76ms, 영어 결정론 79.19→65.42ms입니다.
서로 다른 시점의 중앙값 비율이며 통계적 보장이나 다른 장비의 예상치는 제시하지 않습니다.

전체 생성 Go 96개가 이전 설치본의 대응 파일과 정확히 일치합니다. 모델은 공개한
4,096개 파라미터·16,384바이트 가중치를 그대로 사용했습니다. SHA-256은
`cf00ccc83d17d28ed73fcb869366151a48ffccd3aa8ca8e635aabf19810b9e78`입니다.
추가 학습·새 의도 과제는 0개입니다. 같은 두 파일을 반복한 성능·동작 관측입니다.

응답 시간은 초기 모델 준비와 파일 저장을 제외하고 현재 요청의 생성·실행을
포함합니다. CPU/RSS 표는 현재 실행한 자식만 집계합니다. 컴파일러 부모, 모델만의
RAM, 호스트 전체 CPU 사용률은 측정하지 않았습니다. 특히 최대 단일 자식 RSS의
감소는 Go 버전 자식이 사라진 결과이며 전체 요청 메모리 감소로 환산하지 않습니다.
macOS arm64 한 장비에서 Go1.27.1로 측정했고 캐시·스케줄링 변동이 남습니다.

## 기록과 완전성 지표

새 runtime v3에는 원래 `source_check`, 정확한 버전 출력과 해시 결속을 가진
`toolchain_reference`가 있습니다. 보관된 확인을 사용한 요청의 현재 `toolchain`
프로세스는 비어 있습니다. 버전·빌드를 모두 재사용하면 현재 자원 분모는 실제
실행 두 개입니다. 버전만 재사용하고 바디를 다시 빌드하면 분모는 세 개입니다.

새 비교 도구로 이전 v2 기록 8쌍을 읽었고 기존 비교 결과와 바이트 단위로 일치했습니다.
현재 v3 기록 16쌍을 읽었으며, v2→v3 네 비교는 `INCOMPARABLE_SCOPE`와 숫자 변화
없음을 유지합니다. 측정 계약이 바뀐 프로세스 수를 완전성 향상으로 계산하지 않습니다.
읽기는 기록의 일관성을 확인하며 새로운 실행이나 모델 판단을 수행하지 않습니다.

원래 측정 소스는 `a7fe6d4f9bc3a846dbad6fbff8e90f8bc7c309ae`입니다.
dev와 배포된 main은 파일 내용이 같고 이력이 달라 첫 PR은 충돌했습니다. 두 부모의
tree 일치를 확인하고 정상 병합으로 이력을 연결한 최종 후보는
`1e8c7e97ddc1bf757e2579284bc5434ef56c7747`이며 측정 소스와 tree가 같습니다.
최종 후보로 새로 8회 생성·4회 모델 판단·16회 실행을 수행해 1,024/1,024와
기존 생성 Go의 일치, 첫 버전 확인의 보존·반복 재사용을 재확인했습니다.

## 재현과 원본

개발 CI 실행 `37123599773`의 아티팩트 `11274710082`와 원래 ZIP을 함께
공개합니다. ZIP SHA-256은
`06bab8cbb69709a3fc73620691d703d8798c7dcc1e056c755c5a98dbb0abe4e3`이고
소스 `1e8c7e97`·PR #1192·dev 대상에 결속한 증거의 독립 검증이 통과했습니다.

`observations.zip`에는 입력, 모든 생성·실행·응답, 시간 원본, 원래 실패, 비교 결과가
들어 있습니다. 개인 경로 두 해시 목록은 파일명 목록으로 옮겼고 공개 Go 수집기의
Go 위치는 환경 변수로 받습니다. 민감값·전체 환경·자격 증명은 포함하지 않습니다.

Go1.27.1에서 수집기를 빌드하고 기존·개선 컴파일러를 명시합니다. 입력은 압축을
풀면 나오는 `inputs` 폴더입니다. 같은 공개 모델의 `model.json`과 `weights.bin`을
한 폴더에 둡니다. 비교 기준 생성 코드는 입력 폴더 옆의 `raw-computes-installed`
폴더에서 읽습니다. 이 폴더는 [앞선 설치 원본](../raw-body-usability-20261003)의
`installed-main-native.zip`에 있습니다. 각각 깨끗한 체크아웃에서 `go build ./cmd/gooo`로
기존 `eb8477d5`와 측정 후보 `a7fe6d4f`의 실행파일을 준비합니다.

```sh
go build -o /tmp/gooo-paired ./publication/toolchain-version-reuse-20261003/paired.go
GOOO_LOCAL_GO=/absolute/path/to/go1.27.1/bin/go /tmp/gooo-paired \
  /absolute/path/to/baseline-gooo /absolute/path/to/candidate-gooo \
  /absolute/path/to/inputs /absolute/path/to/model.json /tmp/fresh-paired-results
```

수집기는 각 호출을 제한 시간 안에서 기다리고 완료 전 소스를 수정하지 않습니다.
모든 입력·실행파일·가중치의 수집 전후 해시를 확인합니다. 새 출력 경로가 필요합니다.

첫 로컬 컴파일은 사용하지 않는 `runtime` import로 실패했고 제거 후 세 패키지의
일반·race 검사와 전체 vet가 통과했습니다. 첫 비교 요약은 실제 `.dimensions` 대신
없는 `.axes`를 읽어 멈췄습니다. 비교기는 이미 정상 결과를 냈고 요약 경로를 고쳤습니다.
첫 공개 복사는 경로 변환 표현식 오류로 멈췄습니다. 원본·첫 실패를 보존하고 공개
사본만 정리했습니다. 시간이나 동작을 좋게 보이도록 실패를 삭제하지 않았습니다.

## 공개 연구 CI의 별도 산술 실패

연구 소스 `2b30367b`의 [CI 실행 37123966071](https://github.com/kimjooyoon/gooo-neural-decision-experiments/actions/runs/37123966071)은
19개 작업 중 18개가 통과했고 `full-input-initial-replay`가 실패했습니다.
앞선 공유 모델의 고정 결과와 Linux 산술 재현의 요약 항목 101개가 달랐습니다.
예를 들어 제공된 예시 충족 수 7,560과 새 관측 7,563을 그대로 남겼습니다.
[앞선 수치 이동성 기록](../../docs/full-input-numerical-portability-followup-20261003.md)에도
101개 요약 항목의 차이가 보존되어 있습니다. 최신 기록의 모든 항목이 이전과
동일하다는 주장은 하지 않습니다. 현재 전체 후보 판단기와 별도 산술 재현 작업은
각각 통과했습니다. 연구 워크플로 전체는 FAIL로 기록합니다.

`research-legacy-arithmetic-original.txt`, 구조화한 전체 차이와 실행·작업·소스 결속
파일을 공개합니다. 고정 정답을 현재 숫자로 덮어쓰지 않았습니다. 이 기록의
101개 차이는 본문의 두 과제 반복 실행 12,288개 기대값과 별도로 읽습니다.
