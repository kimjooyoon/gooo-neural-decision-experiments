# 실행 도구 때문에 멈춘 요청을 다루기

2026-10-04 KST. 개발 [#1198](https://github.com/kimjooyoon/meta-ontology-go/pull/1198)은
필수 여섯 검사와 내려받은 증거의 독립 검증 뒤 `a0f23f0b`로 정상 병합했습니다.
깨끗한 후보 `9ef577404e93a1dc3443492c145e5eb8e04fc337`의 실제 실행 기록입니다.
같은 개발 트리·당시 main의 단일 부모를 가진 [main #1199](https://github.com/kimjooyoon/meta-ontology-go/pull/1199)도
자체 필수 여섯 검사·독립 증거·승격 결속을 확인한 뒤 정상 병합했습니다. 깨끗한 main
`93fa2742e2f681c86546ee6fc459a76bae640913`를 Go1.27.1로 빌드·설치했습니다.

## 사용하는 사람이 알아야 하는 변화

`--go-bin`에는 Go 실행파일을 지정합니다. Unix에서 FIFO는 상대 프로세스가 쓸
때까지 열기를 기다릴 수 있습니다. 이번 구현은 비차단으로 열고 실제 열린 파일의
종류를 확인해 `Go tool must be a regular executable file`을 남깁니다. 일반 파일을
가리키는 심볼릭 링크도 확인했습니다. 매번 현재 파일 전체를 읽는 해시, 원본
재검사와 두 실제 바디 실행은 유지합니다. 다른 플랫폼은 열기 전 종류 검사와
열린 파일 재검사를 사용합니다. 일반 파일시스템의 입출력 지연은 운영체제에 따라
달라지므로 이 실험의 시간 범위는 아래 실제 FIFO 관측에서 읽습니다.

| 상황 | 결과를 읽는 방법 |
| --- | --- |
| `--go-bin` 경로가 없음 | 종료 1, 실행 도구 조회 오류와 보존한 요청 확인 |
| 실행 권한이 있는 FIFO, 쓰는 상대 없음 | 종료 1, 일반 실행파일 요구 안내, native 미실행 |
| `native unobserved` | 현재 바디 실행 시간을 관측하지 못함 |
| 실패 요약 `0/128`와 native 0회 | 이 사례의 기대값 128개는 미관측; 원래 종료 상태와 runtime 기록을 함께 읽음 |
| 실제 관측한 기대값의 불일치 | 원래 기대값·출력·충족 수·분모를 유지하고 다음 조립의 근거로 사용 |

공구를 고친 뒤 새 `--out` 폴더로 실행하면 원래 실패 폴더도 남습니다.
모델 경로를 생략한 요청은 결정론적으로 조립합니다. `--timing`은 단계 기록을
추가하고 `--verify-timing --out 결과폴더`는 저장 파일을 읽기 전용으로 확인합니다.
이 확인은 모델을 호출하거나 바디를 다시 실행하지 않습니다.

## 원래 멈춤과 실제 수정 관측

원래 후보 `08f2d813`에서 컨트롤러가 중단된 뒤 해당 프로세스가 내부 60초 제한을
넘겨 살아 있었습니다. 후속 운영체제 조회에서 최소 157초의 생존과 부모 PID 1을
관측했습니다. stdout/stderr와 실행 receipt는 없었습니다. 정확한 명령·PID·자기
프로세스 그룹을 확인해 종료하고 전후 조회와 입력 네 파일을 보존했습니다.
`fifo-interrupted-observation.json`은 중단된 관측을 그대로 설명합니다. 계획했던
68초 제한 결과 JSON은 출력되지 않았으므로 완료된 제한 시간 실험 수에 넣지 않습니다.

구현 전 테스트는 `executable hash waited for FIFO writer`로 실패했습니다. 쓰는
상대를 열어 기다리던 테스트를 합류시킨 뒤 실패를 반환합니다. 누락한 import의
컴파일 실패도 따로 보존합니다. 수정 후 단위 검사·race·vet·Go1.27.1 현대화
고정점 검사를 통과했습니다. 일반 파일 심볼릭 링크와 기존 파일 변경 검사도 유지합니다.

후보의 실제 FIFO 요청은 **전체 CLI 604.14ms**, 기록된 요청 응답 **7.2885ms**,
실패한 공구 해시 단계 **0.033959ms**였습니다. 초기 준비와 저장 범위가 달라
이 시간을 더하거나 같은 값으로 취급하지 않습니다. 외부 5초 제한에 도달하지
않았고 프로세스 종료를 기다려 확인했습니다. 모델 판단·바디 실행 0회,
128개 기대값 미관측, 종료 1과 `native unobserved`를 남겼습니다.
저장 기록의 읽기 전용 검사 한 회가 통과했습니다.

## 일반 실행과 같은 시간창의 비교

기존 한영 두 원본과 모델·결정론 네 조건을 main `93c6463d`와 후보 `9ef57740`에
번갈아 전달했습니다. **이전 → 후보 → 후보 → 이전**, 창마다 여섯 요청입니다.
전체 96회 생성·48회 실제 자체 모델 판단·192회 바디 실행에서
**12,288/12,288 유한 기대값과 96개 고정 생성 Go**가 일치했습니다.
저장 기록의 읽기 전용 검사 16회도 통과했습니다.

| 관측 | 이전 main | 후보 |
| --- | ---: | ---: |
| 최초 응답 중앙값, 각 8회 | 302.69ms | 301.50ms |
| 재사용 응답 중앙값, 각 40회 | 21.54ms | 22.07ms |
| 재사용 응답 범위 | 20.10–26.88ms | 20.24–26.58ms |

후보 단독 확인에서도 성공 8회·판단 4회·실행 16회에서 1,024/1,024와 생성 Go가
일치했습니다. 추가 공구 조회 실패 한 요청은 128개 기대값 미관측으로 남겼습니다.
이 후보의 단독 재사용 22–29ms와 앞선 main 설치 관측 60–69ms를 보고 비교 실험을
추가했습니다. 같은 시간창에서는 양쪽이 함께 빨라졌고 범위가 겹쳤습니다.
이번 성과는 FIFO 대기 문제의 해소와 구체적인 실패 안내입니다. 속도 개선은 이
자료에서 확인되지 않았습니다. 앞선 느린 수치도 원본으로 보존합니다.

CPU/RSS는 현재 자식 프로세스의 집계입니다. 부모 컴파일러·모델 단독 RAM과 호스트
CPU 사용률은 미관측입니다. macOS arm64, Apple M4, Go1.27.1에서 기존 두 의도를
반복했으며 새 의도와 학습 갱신은 0개입니다. 자체 모델 4,096 FP32 매개변수,
16,384바이트 가중치의 SHA256은
`cf00ccc83d17d28ed73fcb869366151a48ffccd3aa8ca8e635aabf19810b9e78`로 같습니다.

## 원본과 재실행

새 설치본은 한영 모델·결정론 성공 8회·판단 4회·실행 16회에서 1,024/1,024와
이전 생성 Go를 유지했습니다. 모델 재사용 응답은 한영 26.54·27.57ms, 결정론
25.50·25.99ms였고 최초 응답 662.41·474.39·302.57·301.94ms도 보존합니다.
공구 조회 실패와 FIFO 실패는 각각 종료 1·판단 0·실행 0·기대값 128개 미관측입니다.
실제 설치 FIFO는 전체 CLI **19.665ms**, 요청 응답 **5.527ms**, 실패한 공구 해시
**0.042458ms**였습니다. 위 후보 최초 604.14ms와 준비·캐시 조건이 달라 두 관측을
별도로 보존합니다. 성공·실패의 저장 기록 읽기 전용 검사 여섯 회가 통과했습니다.

위키의 가장 작은 변수·조건 분기 예제도 설치본에서 별도로 두 번 조립했습니다.
모델 판단 0회·실제 실행 4회에서 **6/6**과 원래 생성 Go 두 개가 일치했습니다.
첫 응답 656.44ms, 재사용 26.60ms이며 저장 기록 확인 한 회도 통과했습니다.
이 작은 예제의 분모는 한영 128개 기대값과 따로 읽습니다. 기존 과제의 반복이며
새 의도·학습 갱신은 0개입니다.

- `native-control.zip`: 후보의 FIFO 요청, 성공·공구 조회 실패, 96회 비교 원본,
  중단된 관측의 입력, 현재 고정 원본·기대값. 모든 파일과 닫힌 목록을 대조합니다.
- `paired-summary.json`, `candidate-smoke-summary.json`, `fifo-summary.json`:
  집계와 소스·바이트 결속. `candidate-fifo-timing.json`에 개별 단계가 남습니다.
- `first-tests.raw`, `implementation-compile-failure.raw`: 원래 실패.
- `corrected-tests.raw`, `race-tests.raw`, `vet.raw`, `modernizer.raw`: 실제 로컬 검사.
- `dev-proof-verification.json`, `dev-merge.json`, `promotion-inputs.json`:
  정확한 개발 소스 증거와 현재 main 승격 입력.
- `main-proof-verification.json`, `promotion-authorization.json`, `main-merge.json`,
  `installed-buildinfo.txt`: 별도 main 증거·현재 참조 재확인·정상 병합·설치 생산자 결속.
- `installed-native.zip`: 새 main의 성공·공구 조회 실패·FIFO 실패·변수/분기 예제 원본.
  `installed-smoke-summary.json`, `installed-fifo-summary.json`,
  `installed-quickstart-verified.json`에 각 범위를 따로 집계했습니다.
- `cleanup.json`: 익명 공개 보관본과 바이트·닫힌 목록을 확인한 중복 896개 파일,
  27,398,056바이트를 개별 재확인 뒤 정리했습니다.
- `paired/main.go`, `smoke/main.go`, `fifo-probe/main.go`, `archive-readback/main.go`:
  Go 수집기·원본 대조기. 작은 배열과 기존 자체 모델을 사용하며 별도 큰 모델 다운로드는 없습니다.

```sh
unzip native-control.zip -d saved
go run ./archive-readback native-control.zip saved
gooo body-path-run --verify-timing --out saved/fifo-native/results
go run ./fifo-probe /path/to/clean-gooo saved/inputs fresh-fifo SOURCE_SHA
```

수집기는 깨끗한 바이너리의 생산자 소스를 확인합니다. 위 FIFO 수집기는 Unix용이며
생성한 FIFO를 종료 확인 뒤 제거합니다. 일반 명령의 입력 준비·한영 모델 사용은
[위키 실행 안내](https://github.com/kimjooyoon/meta-ontology-go/wiki/File-Based-Body-Run)에서
읽을 수 있습니다. 작은 반복 비용 실험은 [다음 계획](../owned-hash-reader-20261004/NEXT.md)에 연결했습니다.
