## Compiler and model roles

The Gooo compiler constructs legal typed alternatives, binds the original
source, supplies structural facts and checks actual finite behavior. Our small
model ranks alternatives from source and Korean/English intent. Actual failures
can supply later ranking context. Deterministic continuation handles disconnected
inference or representation overflow. A model score never proves correctness.

The system records input/source/model/test hashes and PROV-O derivations. Go
collectors, independent arithmetic audits, calibration selection, codegen,
generated-Go execution and public byte verification provide the development
measurements. Human review and Guardian are not steps in this loop.

## Next separately frozen experiments

| Study | Change to investigate | Preserve and measure |
|---|---|---|
| Source representation | Distinguish source/order effects behind retained identical-input conflicts using compiler facts | Full inputs, collisions and target ties by split, Go feature parity, source projection time/heap use |
| Joint path judgment | Rank four legal two-choice masks together instead of combining independent marginals | Full correlated finite-mask targets, complete-function curves, actual feedback predictions, typed rejections |
| Korean/English judgments | Broaden public natural expressions and action/order/reference descriptions | Functional contract and language agreement separately; exact full UTF-8 inputs; shared-wording limits |
| Quantized repeatability | Several preregistered random seeds and fixed FP/PTQ/QAT objectives | Every seed/variant and negative selection result; packed/resident bytes; repeated warm and native timings |

New ABI/head changes require their own model metadata and compiler compatibility
study. The current 12,728-parameter/1,248-byte-workspace contract and source-v3
header remain available for replay. A proposed joint model is not an implemented
API or a reason to change current weights. Set memory/update budgets before
optimization, then publish all predeclared outcomes.

## Machine-readable measures to keep

1. Complete functions and ordered passing cases at candidate budgets 1–4.
2. Extra candidates to completion and actual initial/feedback predictions.
3. Unattempted masks, type rejections, cancellation and zero-call declines.
4. Input representation conflicts, finite equivalence ties and joint target mass.
5. Paired-language initial choices, distinguishing agreement from correctness.
6. Warm prediction time/allocations, source projection cost, native child CPU/RSS
   and wall time, with startup and host utilization reported separately.
7. Offline optimizer updates/time/MPS memory and exact published weight hashes.

Autonomous progress should be judged by lower construction cost while retaining
the complete authored contract and all partial/failure evidence. Four finite
alternatives being exhaustible is not general semantic completeness. Releasing
experimental candidates need not imply default compiler model promotion.
