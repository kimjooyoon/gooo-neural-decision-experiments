# Full-input model SDK and native Gooo integration

Registered before trained-model SDK/native collection. This continues the
[full-input protocol](full-input-judgment-preregistration-20261003.md) and the
[paired arithmetic study](full-input-separate-arithmetic-results-20261003.md).
The compiler and SDK observations below have not yet been collected.

## Fixed artifacts and scope

Use all twelve models from `publication/full-input-separate-arithmetic-20261003`:
four arms (positioned-original, positioned-varied, bag-original, bag-varied),
three variants (FP32, PTQ, QAT), both expanded and compact layouts. Require
`arithmetic_version: float32_separate_v1`. Bind every file to the closed public
manifest at research revision `600dc282fb059918c0fd6588d955d3a56c380b58` and
Hugging Face revision `7c4501789b34d885c14ab54aee1d40995eb8b1e6`.

Weights, wording, targets and training checkpoints stay fixed; optimizer updates
are zero. All arms retain their own results and regressions. The existing model
default stays in place. This is an explicit model integration and execution
study over known authored tasks; remaining split/form analyses and new task
generalization remain part of the original protocol.

## Native compiler implementation and collection

Dispatch expanded V3/V4 models by their declared feature version through strict
loaders; compact loading enforces the same closed metadata. Record the actual
feature and arithmetic identity in retained-model information, context receipts
and initial/feedback decisions. Complete caller text remains available in decline
receipts; unsupported or oversized input continues deterministically with zero
predictions. Exercise these contracts with controlled synthetic weights first.

Freeze and build the clean compiler source with the released SDK, then reuse the
16 Gooo views from the prior compact-native protocol: eight authored composition
families, Korean/English, configuration 20, goal 4. Run all twelve explicit models
in both layouts, alternating layout order after each view, plus one disconnected
arm per view: **400 generations**. Keep an unseeded budget of eight candidates,
one candidate per advance, seven feedback rounds and the existing unfixed-choice
optimization. Supply no CI hint. Record actual initial/feedback prediction counts.

Immediately build and run each emitted Go program twice. Each view retains the
same independent 24-input case suite as the prior protocol (including eight
inputs disjoint from the current selection suite): **800 compiled executions,
9,600 finite generation/case expectations and 19,200 ordered outputs** if complete.
Record actual denominators and all incomplete/error prefixes rather than assuming
these planned totals occurred. No new holdout intention is introduced.

Within each arm/variant/view, require exact expanded/compact generated Go,
unseeded candidate path and finite behavior after normalizing only artifact
identity, artifact-bound chain hashes and measured timings. Preserve all original
receipts. Independently consume completeness/progress/runtime receipts using the
same compiler source; check original source, generated bytes, parent bindings,
model identity, call accounting and the first unresolved completeness dimension.
Keep prediction timing, whole codegen, model load, native build, execution CPU/RSS
and full collector time distinct. Use no concurrent local source builds during
timing collection. These observations do not select a new default checkpoint.

and inventory the original study's retained evidence before collection. Allow

the existing 768 MiB study increment and 3 GiB combined own-three limits. Bound
