# Next bounded Gooo / Korean / English judgment experiments

The immediate development target is usable partial construction with visible
uncertainty and bounded iteration cost. First-shot label accuracy is one
observation. A sparse passing test cannot certify the instruction: the current
English subtraction example makes that limit concrete.

## Compiler and model roles

Gooo source binds stable identities, types, variable scope and legal path slots.
The tiny model ranks the declared alternatives from Korean/English instruction
and structured Gooo context. Deterministic construction, finite tests and optional
diagnosis record the results. A diagnostic witness supplies two observed outputs;
an expected answer must come from an explicit authoritative source contract or
test definition. Model confidence alone does not create it.

Preserve source, plan, tests, model, CI and output digests as separate provenance
entities and link each ranking/construction/diagnosis activity to its inputs.
Rejected paths, partial results and conflicting tests stay in the event history.
CI status is context for iteration; it cannot silently redefine the Gooo goal.

## Next data scope

Preregister new intention groups before capture and reserve groups for evaluation.
Separate variable naming, nested conditionals, branch polarity, comparisons,
operand order, assignment target/source, arithmetic operation and branch
placement. Include Gooo structure plus Korean/English instructions, synonyms,
omitted details and explicit contradictions. Repeated translations and budgets
must not count as new independent tasks. Existing development examples, including
the English negative selection, must not become an untouched accuracy benchmark.

For each finite contract, compute the set of reachable passing paths. Train
soft targets over that set rather than inventing one uniquely correct label
when several paths satisfy the evidence. Keep separate supervision for an
explicit Gooo semantic target; finite equality does not imply intent equality.
Record unresolved labels and contradictions. If new test expectations are added,
bind them to a new test-suite digest and keep the earlier sparse result.

## Measurements and model changes

Report committed-candidate completeness, attainable finite completeness,
unobserved path count, case-indistinguishable alternatives, witness yield,
Korean/English body agreement, model calls per added finite pass, latency and
process memory. Include zero-gain feedback, abstention and negative results.
Progress-only checkpoints must not inflate completion. Candidate budgets and
diagnostic budgets are separate denominators.

Compare the existing parent, own FP32 and ternary variants before considering
a new checkpoint. Limit the next GPU training run to a preregistered small
corpus and step budget; preserve its source/data/seed pins and failed runs.
Go remains runtime and orchestration. Offline training may use Python. Packed
ternary disk storage and decoded int8 computation are separate measurements.
This plan performs no new training and makes no checkpoint promotion claim.

## Repository verification cost

The completed native feature CI run 36843870308 has an observed creation-to-last
update span of 1,047 seconds. Its six canonical job durations are 63 s for format,
54 s for vet, 241 s for ordinary tests, 559 s for race tests, 450 s for semantic
conformance and 216 s for policy/proof work. They overlap and cannot be added.
Start offsets also include dependencies and scheduling, not just runner queueing.
The [raw timestamp observation](../publication/path-diagnosis-feature-ci-cost-observation-20261001.json)
is one run and does not measure CPU consumption or causal bottlenecks.

Future cost work should first measure which optional workflows cover changed
surfaces, shared build preparation and duplicate checks, while preserving exact
source/proof binding for main promotion. Local model and diagnostic latency are
recorded separately from repository delivery time. The existing optional
historical implementation-only certificate rejects a broader identity change;
its failure should expose which identity axes differ and preserve evidence,
without claiming an implementation-only certificate for that transition.
