# 다음 실험: 현재 값과 저장값을 모델에 전달하기

2026-10-05. 이 문서는 구현·학습 전에 기록한 다음 실험 계획입니다.

## 관측에서 출발

순차 필드 실험의 공개 QAT 모델은 `copy.state`와 `saved.state`를 같은
768칸 특징 배열로 받았습니다. 전체 문맥의 지문은 다르지만 계산 입력과
응답은 같습니다. Gooo 실행기는 두 변수의 현재 값과 복사 시점을 구분합니다.
이 차이를 판단기에 전달하는 것이 다음 작업입니다.

예를 들어 메모를 복사해 두고 원본의 상태를 바꾸면 두 메모의 상태가 달라집니다.
모델에게는 식의 이름과 함께 어느 시점의 메모를 읽는지도 알려 줍니다.

## 언어가 계산할 작은 관측

타입을 검사한 본문에서 선택 위치까지 읽고 아래 정보를 결정론적으로 계산합니다.

| 관측 | 의미 |
| --- | --- |
| 지역 정의 번호 | 이 지역 변수의 선언 위치와 범위 |
| 필드 정의 번호 | 해당 필드를 마지막으로 쓴 위치 |
| 복사 시점 | 저장한 레코드·문자열이 가져온 당시 정의 |
| 읽기 의존 | 후보식이 실제로 읽는 지역 변수와 필드 |
| 조건 경로 | 대입이 실행되는 분기와 합류 지점 |
| 해석 상태 | 확인한 출처·여러 가능성·지원 범위 밖 구분 |

소스 위치와 안정된 필드 ID를 유지합니다. 이름만 바꾼 소스에서는 동일한
출처 관계가 나오게 합니다. 분기 뒤 값이 두 정의 중 하나일 때는 둘을 남깁니다.
현재 입력의 실제 값이나 테스트 정답을 계산 입력에 넣지 않습니다.

새 관측은 기존 표현에 덧붙이는 별도 버전으로 설계합니다. 기존 모델·특징·
실행 기록의 의미를 유지합니다. 모델을 생략한 경로는 기존 후보 순서로 실행됩니다.

## 작은 범위의 첫 구현

첫 단계는 required Text 레코드의 지역 대입·복사·필드 읽기입니다. 고정 배열에
정의와 읽기 간선을 저장하고, 한도를 넘으면 정확한 해석 상태를 반환합니다.
분기·조기 반환은 다음 단계에서 추가합니다. 해석하지 못한 관계를 현재 값으로
추측하지 않습니다. 모델 입출력 파일·출처 관측의 크기와 할당 수를 기록합니다.

## 실험을 나눠 읽기

1. **표현 검사**: 현재값·저장값·쓰기 순서가 다른 소스의 입력 충돌을 셉니다.
   이름 변경·줄바꿈만 다른 소스의 출처 관계도 비교합니다.
2. **혼합 요구**: 세 선택의 여덟 목표 조합을 균등하게 준비합니다. 유지·변경·
   부정 표현을 한영으로 작성하고 새 표현 묶음은 학습에 쓰지 않습니다.
3. **작은 판단기**: 먼저 기존 특징과 새 관측을 각각 읽는 같은 크기의 모델을
   비교합니다. 그 다음 필요한 경우에만 소량 학습하고 FP32·QAT를 비교합니다.
4. **실제 조립**: 후보 하나·둘·여덟 예산으로 선택 사례와 별도 실행 입력을
   평가합니다. 분기에서 그대로 유지된 필드와 바꾸어야 하는 필드를 따로 셉니다.
5. **비용**: 출처 분석·특징 준비·추론·후보 평가·빌드·실행 시간을 각각 측정합니다.
   첫 호출과 반복 호출, 프로세스 RAM과 모델 배열 크기도 구분합니다.

모든 관측에는 분자·분모, 실패 소스, 변경되지 않은 가중치의 지문을 남깁니다.
첫 실험은 원본 8MiB를 목표로 하고 결과를 보며 범위를 공개합니다.
높은 한 번의 정답률보다 서로 다른 요구를 구분하고 남은 기능을 설명할 수
있는지를 봅니다. 이 계획은 완료된 실험 수에 포함하지 않습니다.
