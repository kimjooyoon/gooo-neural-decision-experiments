# Gooo 독자 소형 모델 개발 방향

## 후속 진행 — 2026-10-03

아래 본문은 10월 2일의 출발점과 계획을 보존합니다. 이후 직접 소스 특징,
공동 경로 판단, 2,072개 파라미터 공유 모델, Go SDK v0.2.14 연결을 진행했습니다.
현재 안내는 [Gooo 언어 방향](https://github.com/kimjooyoon/meta-ontology-go/blob/main/docs/language-direction.ko.md)과
[연구 저장소의 최신 요약](../README.md)에 있습니다.

전체 입력을 유지한 네 학습 조건의 [초기 결과](full-input-judgment-initial-results-20261003.md)는
12개 FP32/PTQ/QAT 모델과 함께 공개됐습니다. 기존 개발 과제에서 FP32 첫 경로
충족 수는 113→368/512, 추가 시도는 1,469→186이었습니다. 연산 순서의 특징
충돌, 양자화 손실, [환경별 후보 순위 차이](full-input-numerical-portability-followup-20261003.md)가
다음 과제입니다. 새 V4 계약은 연구 실행기에서 평가 중이며 컴파일러 반영은 남아 있습니다.

## 10월 2일의 기준

자체 초기화한 12728 파라미터 모델을 Gooo main의 선언된 IR 경로 선택에
직접 사용했다. 한국어·영어 의도, 변수 참조·할당, 피연산자 순서, 분기 배치,
실행 순서에 대해 선언된 후보의 순위를 판단했다. 자체 초기값과 Gooo 학습
자료를 사용했으며, Laya 실험에서 익힌 구조화된 호출 방식을 발전시켰다.

이번 한영 일치 학습은 840 GPU 업데이트, 모델 9개, Go 판단 4608회와
실제 컴파일러 120회로 측정했다. PTQ의 추가 후보는 143→135회로 줄었지만
개선 8회는 한국어 변수 할당에 집중됐다. FP32에는 개선이 없었고 보정
데이터가 고른 QAT는 평가 데이터에서 FP32보다 추가 후보를 더 사용했다.
이 결과를 모델 크기를 무작정 키우는 근거로 사용하지 않는다.

## 다음 구조 실험

**컴파일러가 의미 특징을 만들고, 모델이 합법 후보를 순위화한다.**
현재 256차원 중 구조 64차원을 문자열 해시 대신 다음 결정론적 투영으로
바꾸는 실험을 사전 등록한다. 자연어 192차원과 48개 은닉 유닛은 대조군과
같게 유지해 표현 변화의 영향을 측정한다.

| 결정 영역 | 컴파일러가 제공할 정보 | 모델의 역할 |
|---|---|---|
| 변수 참조 | 정의 위치, 사용 위치, 타입, 도달 가능한 정의 | 현재 사용에 맞는 합법 정의 선택 |
| 변수 할당 | 대상 슬롯, 이후 사용, 값의 출처 | 의도에 맞는 대상 슬롯 선택 |
| 조건·분기 | 조건 연산자, 참/거짓 경로, 각 경로의 효과 | 분기 배치와 의미 연결 선택 |
| 피연산자 | 교환 가능 여부, 순서에 따른 의미, 타입 | 선언된 순서 후보 선택 |
| 실행 순서 | 정의 전 사용, 데이터 의존 간선, 효과 순서 | 의존 관계를 지키는 실행 후보 선택 |

이 특징은 검증된 원본 소스와 IR에서만 생성한다. 초기 입력에 정답, 테스트
예상값, 관측 결과나 CI 결과를 넣지 않는다. 이름 변경·숫자 변경 대조군을
두어 표면 표현에 대한 의존과 의미 판단을 구별한다. 범위를 넘는 입력은
명시적으로 거부하고 결정론적 후보 탐색을 계속한다.

공유 은닉층 위에 영역별 2개 선택 머리를 두는 별도 대조군도 계획한다.
5개 영역·10개 출력이면 파라미터는 12826개로 기존보다 98개만 늘어난다.
새 특징/출력은 새 ABI로 등록하고 기존 8개 출력 모델과 섞어 읽지 않는다.
우선 새 코호트·특징 정의·대조군을 고정한 후 SDK/컴파일러를 구현한다.

## 완전성과 비용으로 개선하기

평가 단위는 독립적인 프로그램 의도다. 같은 의도의 언어·표현·양자화·재실행을
새 실험 의도로 세지 않는다. 다음 코호트는 새 조합과 새 표현을 사용하고
프로그램과 표현 템플릿을 함께 분리한다.

- 처음 완성된 기능 비율과 테스트 후 완성된 기능 비율을 함께 기록한다.
- 맞는 일부 바디를 유지하며 추가로 조립한 후보 수와 모델 호출 수를 기록한다.
- 변수 연결, 분기 효과, 실행 의존 관계별 미충족 요구를 기록한다.
- 한영 불일치가 줄어도 두 언어가 같은 오답을 내는지 별도로 확인한다.
- 지연 시간, 프로세스 메모리, 실제 연산 비용을 같은 환경의 대조군과 비교한다.

CI 결과는 최초 판단과 분리한 후속 피드백에만 전달한다. 후보가 준비되면
즉시 타입 검사·테스트·후속 판단을 진행하고, 모든 후보 생성이 끝날 때까지
기다리는 배치 장벽을 넣지 않는다. 병렬 실행은 작업별 배열 작업공간,
제한된 작업자 수, 취소·시간 제한과 종료 기록을 갖춘 별도 실험으로 검증한다.

모델 채택은 시스템 지표로 결정한다. 새 코호트에서 완전성을 유지하면서
추가 후보·호출·시간 비용을 개선한 모델만 자동 채택 대상으로 삼는다.
실패한 모델도 실험 가중치와 결과를 공개한다. 사람의 필수 리뷰나 모델의
자신감 점수를 통과 조건으로 추가하지 않는다.

## PROV-O와 공개

원본 소스, 계획, 데이터, 모델, 판단, 후보, 테스트 결과는 `prov:Entity`로,
학습·판단·조립·실행은 `prov:Activity`로 연결한다. `prov:used`,
`prov:wasGeneratedBy`, `prov:wasDerivedFrom`에 내용 해시와 버전을 기록한다.
출처 기록은 결과를 추적하기 위한 것이며 모델의 임의 소스 변경 권한을
부여하지 않는다.

실행·연결·감사·공개 도구는 Go로 유지한다. Python은 오프라인 GPU 학습과
내보내기에 한정한다. FP32, PTQ, QAT를 모두 비교하고, 삼진 저장 1.6비트와
실제 int8 상주 메모리를 구별해 공개한다. 기존 증거는 Git 커밋과 HF 커밋에
고정하고 새 모델과 결과는 새 경로에 추가한다.
