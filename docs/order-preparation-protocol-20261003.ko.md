# 전체 후보 판단의 준비 비용 줄이기

2026-10-03 작성·후속 갱신. **SDK 비교와 반복 컴파일러 API의 생성·실행 측정을 완료했다.**
최초 계획은 `edc021f`에 보존했다.

[공개된 결과와 모든 원본](../publication/order-prepared-sdk-20261003)에서 기존·매번 준비·재사용
경로를 비교했다. 추가 학습 없이 3,840회 탐색·1,920회 모델 판단의 전체 선택 기록이
일치했다. 첫 메모리 측정에 결과 직렬화 버퍼 회수가 섞인 문제와 수정 후 관측도 남겼다.

[컴파일러 후속 관측](../publication/order-prepared-native-20261003)은 같은 64개 요청에서
512회 생성·512회 판단·1,024회 실제 실행을 완료했다. 후보를 재사용하는 두 번째 호출의
생성 중앙값은 1.02→0.69ms, 조립 계획 전개·모델 준비까지 합치면 2.22→1.63ms였다.
기존 전체 선택과 실행 결과가 일치했고, 첫 실행 도구의 오류 두 건도 보존했다.
이는 같은 리비전의 신규/유지 생성기를 비교한 API 관측이다. 이전/이후의 새 CLI 프로세스
짝 비교는 아직 수행하지 않았으며, 과거 CLI 수치와 직접 개선율을 계산하지 않는다.
컴파일러 변경은 #1178과 #1179의 전체 CI를 통과해 dev·main에 병합하고 설치했다.
설치본에서도 16회 생성·32회 실제 실행, 128/128 유한 기대값을 확인했다.
[설치·CI 원본](../publication/order-prepared-installed-main-20261003).

## 관측과 작은 가설

[컴파일러 직접 연결](../publication/order-judge-native-20261003)에서 모델을 쓰면 후보 평가가
96회에서 76회로 줄었지만, 생성 중앙값은 8.58ms에서 9.26ms로 늘었다. 판단 자체는
2.75µs였다. 작은 모델을 반복 호출할 때 같은 준비를 다시 하는 비용을 줄여 본다.

SDK v0.2.19의 `orderjudge.Search`와 `orderfacts.Candidates`를 읽어 확인한 작업:

- 두 함수가 각각 `pathplan.Prepare`를 호출한다.
- `Candidates`는 여덟 조합을 컴파일해 합법성을 확인하고 구조 표현만 반환한다.
- `Search`는 평가할 조합을 다시 컴파일한다.
- 모델의 메타데이터·16 KiB 가중치를 매 호출 직렬화하고 지문을 계산한다.

이 목록은 코드 관찰이다. 각 작업이 전체 지연의 몇 퍼센트인지 아직 측정하지 않았다.
성능 가설은 **변하지 않은 조립 도면·후보·모델을 한 번 준비해 여러 요청에서 쓰는 것**이다.

## 구현 경계

컴파일러가 소스와 계획을 연결한 뒤, 소유권이 분명한 준비 객체를 만든다. 이 객체는
허용된 여덟 프로그램, 원본 의도 특징, 후보 특징, 고정 모델의 지문을 보관한다.
전역 캐시나 별도 서비스는 추가하지 않는다. 소스·계획·모델이 달라지면 새로 준비한다.

호출마다 기대값·시도 예산·취소 상태·작업 배열·결과 기록을 새로 가진다. 이전 요청에서
선택된 답을 다음 요청의 정답으로 간주하지 않는다. 기존 프로그램 객체는 읽기 전용으로
공유하고, 외부에 반환하는 맵과 결과는 각 호출이 소유한다.

학습 중 `Fit`은 가중치를 갱신한다. 따라서 모델 생성 시점의 지문을 학습 이후에도 쓰는
방식은 피한다. 학습이 끝난 불변 모델을 로드하거나 별도 준비 객체를 만들 때 지문을 정한다.
기존 V3/V4와 첫 실험의 소스 목록은 보존하고 별도 버전으로 비교한다.

## 비교 조건과 분모

가중치 SHA256은 `cf00ccc83d17d28ed73fcb869366151a48ffccd3aa8ca8e635aabf19810b9e78`로
고정한다. 추가 학습은 0회다. 이미 관측한 64개 `new-template`·`new-constants` 요청,
시도 예산 1·8, 결정론·모델 조건을 비교한다. 범용 자연어 평가로 확대 해석하지 않는다.

| 조건 | 측정할 구간 |
| --- | --- |
| 기존 Search | 지금의 전체 준비·판단·평가·기록 |
| 매번 준비하는 새 Search | 새 준비 객체 생성부터 결과 반환까지 |
| 준비 객체 재사용 | 준비 비용을 별도 기록하고 매 호출 판단·평가·기록 |
| 컴파일러 사용 | 새 CLI 프로세스와 모델·후보를 보유한 반복 생성 각각 |

먼저 작은 재현을 통과한 후 전체 요청으로 늘린다. 같은 요청·조건을 짝지어 비교하고,
반복 순서를 교대한다. 준비 1회 비용, 호출 수, 중앙값·p95, 바이트·할당 수와 유지 메모리를
기록한다. 재사용 횟수에 따라 준비 비용을 포함한 누적 시간이 언제 유리해지는지도 공개한다.
전체 CLI 비용과 예측 커널 비용은 각각 표시한다. 계획된 반복을 완료된 결과로 세지 않는다.

## 의미 보존과 실패 기록

전체 예측 배열, 후보 순위·별칭, 평가 순서, 선택 코드, 유한 예시 결과가 기존 기록과
같아야 한다. 시간 필드만 이름을 명시해 비교에서 제외한다. 취소, 마감시간, 서로 다른
기대값, 소스 불일치, 호출자 입력 변경, 네 동시 호출의 결과 소유권도 확인한다.

일치하지 않으면 해당 입력과 최초 차이를 남기고 비교를 중단한다. 느려지거나 유지 메모리가
늘어도 그대로 기록한다. 사용할 객체 수와 수명을 정한 뒤 컴파일러 경로에 연결한다.
개선 여부는 같은 기능을 끝내는 전체 비용으로 판단한다.
